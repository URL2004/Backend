# 관리자 원장 조회 최적화 (2026-10-02)

## 원인과 범위

일괄 보상을 화면에서 제외하려고 최신 문서를 순차 조회한 뒤 필터링하면서,
최신 1,000건 표시에도 약 39,000건을 가져왔다. 캐시 만료 후 동일 비용이 반복됐다.
조회 실패 시 전체 회원의 하위 원장을 병렬 조회하는 fallback도 제거한다.

잔액 계산, 지급/차감/환불 정책, 사용자 이용 이력, 원장 원본의 금액 필드는 변경하지 않는다.

## 조회 계약

- `type != admin_adjust`: 사용·충전·복원 등 명시적 유형을 가진 기록.
- `adminLedgerVisible == true`: 일반 관리자 조정 및 유형이 없거나 null인 과거 기록.
- 두 스트림을 병렬 조회하고 전체 문서 경로로 중복 제거 후 최신순으로 합친다.
- 지정된 보상 캠페인/문서 ID는 표시용 predicate로 한 번 더 제외한다.
- 각 스트림의 문서 반환 상한은 요청 건수다. Firestore 인덱스 내부 스캔은 별도이며
  문서 반환 건수와 동일하다고 간주하지 않는다.
- 짧은 캐시와 동시 요청 공유는 유지한다. 실패는 캐시하지 않는다.
- 원장 조회 오류는 기존 API 오류 응답으로 전달한다. 전체 사용자 조회로 확대하지 않는다.

## 적용 순서 / 재배포 전제

1. `firestore.indexes.json`의 creditHistory COLLECTION_GROUP 인덱스 두 개만 추가한다.
   기존 인덱스 및 보안 규칙을 삭제하거나 변경하지 않는다.
2. 기존 createdAt 그룹 인덱스로 원장을 한 번 순회한다. 일반 admin_adjust 및 type 누락/null
   문서에만 `adminLedgerVisible: true`를 updateTime 사전 조건으로 추가한다.
   숨김 대상에는 쓰지 않는다. createdAt, 금액, 잔액, 유형, 캠페인 필드는 수정하지 않는다.
3. 인덱스 준비 후 동일 시각 기준 최신 2,000건을 기존 조회와 비교한다.
4. 전체 테스트와 배포 사전 검사를 통과한 코드만 배포한다.
5. 배포 전후 최신 구간을 다시 확인해 구 서버에서 동시에 생성된 일반 조정의 표시를 보완한다.
   신규 일반 조정은 양수 관리자 지급 경로와 음수 차감 경로 모두 서버가 표시 필드를 기록한다.

신규 서버 경로 또는 운영 스크립트가 일반 `admin_adjust`를 만들 때에는 이 표시 필드를 포함해야 한다.
다른 대량 지급을 숨기는 정책은 자동 적용하지 않으며 별도 검토한다.

## 롤백

문제가 있으면 직전 운영 코드로 복귀한다. 표시용 필드와 추가 인덱스는 구 코드에서 무시되므로
재무 원본을 삭제하거나 표시용 필드를 일괄 제거할 필요가 없다.
