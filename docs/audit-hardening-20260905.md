# 엔진·운영 감사 수정 기록 — 2026-09-05

사용자가 제외한 실행 중 취소·중단 UI/기능은 추가하지 않았다. 서버 마감 시간, 배포 종료 처리, 실행권 만료와 복구는 시스템 안정성 작업에 포함한다.

## 실행·정산 계약

- 접수 중인 UID를 프로세스 안에서 잠그고, Firestore의 계정 활동 claim과 실행 lease를 같은 접수 transaction에서 검사한다.
- `transformExecutionLeases/active`는 인스턴스 간 UID 단일 실행, formal/short 풀 상한을 관리한다. 문단 보강과 보존형 재처리도 같은 실행권을 사용한다.
- lease는 90초 유효하며 20초마다 갱신한다. 실행 token이 다른 작업자는 결과를 저장하지 못한다. 계정 삭제 상태도 실행 전에 검사한다.
- 새 결과는 `pendingCompletion`에 먼저 영속화한다. 그 뒤 기존 `job_<id>` 원장 키로 멱등 정산하고 완료 결과를 영속화한 다음 메모리에 공개한다. 저장 또는 정산 실패 시 같은 후보를 복구하며 모델을 다시 호출하지 않는다.
- 문단 보강은 `pendingRefinement`와 기존 `job_<id>_refine<n>` 정산 키를 사용한다. 최종 저장 실패 시 기존 문단이 계속 노출된다.
- 복원은 문서 ID cursor로 전 페이지를 읽는다. 조회 인스턴스에 없는 작업도 Firestore에서 찾으며, 완료 작업 TTL은 종료 시각을 기준으로 한다. 실행 중인 작업과 정산 대기 후보는 TTL로 지우지 않는다.

## 엔진·프롬프트

- HTTP timeout과 상위 AbortSignal은 응답 헤더 이후 JSON 본문을 읽는 동안에도 유효하다.
- 구조화 출력·토큰 부족 재시도의 usage는 응답마다 누적하며, 최종 실패에도 확인된 usage를 남긴다. 응답을 받지 못한 공급자 비용은 추정 확정값으로 기록하지 않는다.
- `added_claim`을 단어 겹침 비율로 무시하지 않는다. 허용 사실은 원문과 명시적으로 제공된 메모·승인 근거이며, 충돌하면 원문이 우선한다. 의미 수리에도 허용 근거를 전달한다.
- 장문 의미 검사는 최대 2구간을 병렬 검사하고 실제 수리가 필요할 때 문서 공통 예산을 원자적으로 차감한다. 결과 조립 순서는 원문 순서다.
- 휴머나이징 전체 실행은 제한된 Worker Thread에서 처리한다. 기본 2개이며 메인 HTTP 이벤트 루프에서 장문 편집 지표를 계산하지 않는다.
- 일본어·중국어를 포함한 외국어 중심 입력을 한국어 전용 경로에서 차단한다. 혼합 기술 용어는 한글 비중 기준으로 허용한다.
- 감지 신호에 문장 번호를 요구하고 서버에서 원문 offset을 검증한다. 위치가 없으면 약한 단일 신호로, 위치가 하나면 단일 신호로 내린다. 이는 위치 검증이며 AI 작성 여부의 확증은 아니다.
- 감지 미리보기는 신규 사실·누락·구조·의미 검사를 통과해야 공개한다. 최대 6초 안에 준비된 미리보기만 사용하며 본 감지가 끝나면 미완료 미리보기는 서버에서 종료한다.

## 문단 보강

- 원문 사실 누락, 새 사실, 인용·구조 손상, 과도한 분량 변화를 검사한다. 별도 의미 검수에서 주장 보존과 메모의 실질 반영이 모두 확인되어야 반영한다.
- 실패·무효 보강도 시도 횟수에 포함한다. 기본 작업별 8회이며 성공한 무료 보강 횟수와 분리한다.
- 보강 완료 시 결과 버전을 올리고 이전 문서의 품질 지표를 무효화한다. 전체 문서를 다시 검수했다고 표시하지 않는다.
- 메모 재사용 진단에는 메모 번호와 횟수만 남긴다. logger도 memo/userNotes/sourceText/outputText 키를 마스킹한다.
- 종료 중에는 새 보강을 받지 않는다. 기존 보강은 시스템 signal을 전달받고 재시작 후 완료 후보를 우선 복구한다.

## 운영 계약

`/healthz`와 `/api/health`는 최소 정보만 반환하는 readiness다. 작업 복원 완료, 설정, Firestore 읽기, 활성 provider 호환성을 확인하고 실패 시 503을 반환한다. 의존성 probe에는 10초 캐시와 동시 요청 병합, 2.5초 마감 시간을 사용한다. `/livez`는 프로세스 생존 확인용이며 상세 설정은 기존 인증된 `/internal/health`에서만 확인한다. 실제 유료 모델 호출의 성공 여부까지 검사하지 않는다.

글쓰기 랩 v2는 **인증된 공개 유료 기능**이다. 관리자 전용 무과금 휴머나이징 실험실과 다르다. 기존 `WRITING_LAB_V2_ENABLED`, UID rollout, 문맥 서명 비밀값, quota 및 정책 팩 검수 계약을 유지한다. 상세 health에 `accessMode: public_paid`와 App Check의 실제 모드를 표시한다.

App Check는 기존 운영 도입 정책에 따라 기본 `off`를 유지한다. 이 상태에서 App Check가 비용 남용을 차단한다고 설명하면 안 된다. 도입하려면 웹용 공급자/site key 설정 및 클라이언트 토큰 발급을 먼저 배포하고 `shadow` 관찰 후 `enforce`로 전환해야 한다. 공급자가 없는 상태에서 서버만 강제하여 정상 사용자를 차단하지 않는다.

`/csp-report`는 16KB 제한과 IP rate limit을 적용한다. 지시문·차단 origin·문서 origin만 기록하며 경로·query·스크립트 내용은 기록하지 않는다.

## 배포 및 검증 범위

1. 현재 production 기준의 두 feature commit을 검토한다. 모든 활성 인스턴스가 새 lease 계약을 사용해야 분산 실행 보장이 성립한다. 구버전 worker가 함께 실행되는 최초 전환에는 진행 작업이 없는 배포 구간을 사용한다.
2. 백엔드를 먼저 배포하여 readiness 및 CSP 수신 경로를 확인한다. 그 다음 프런트엔드를 배포한다.
3. 실환경에서는 readiness, Firestore transaction 재시도율, lease 갱신 실패, 대기 시간, RSS, 모델 호출 비용과 정산 복구를 확인한다.
4. 롤백할 때도 새 버전의 실행 작업이 정리된 구간을 사용한다. 이전 버전은 pending 결과 정산 계약을 알지 못하므로 pending 후보를 남긴 채 되돌리지 않는다.

로컬 테스트는 합성 입력·모의 I/O 기반이다. 실제 결제, 유료 모델 품질 평가, 운영 부하 시험, production 배포는 수행하지 않았다. 운영 환경 변수 변경, App Check 공급자 등록, 인프라 리전 변경과 DB 백업 복구 검증은 이 코드 커밋으로 완료되는 작업이 아니다.
