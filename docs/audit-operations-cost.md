# Attempt and cost evidence

`transformAttemptTrace` observes execution leases without deciding billing, retries, delivery or detection scores. Each acquired execution lease produces a numbered start/resume attempt; status transitions, execution start/end, queue wait, client abort request, observed provider abort failures, committed user charge status, and observed model cost are persisted in `transformJobs.attemptTrace` and exported in `transformJobArchive.attemptLifecycle`.

`preview_completed`, `transform_completed`, `cancelled`, `blocked`, `error` and `unfinished` are separate outcomes. A cancelled client signal does not prove the provider stopped charging. Credits and coupons are never converted to USD or subtracted from provider cost. `unchargedKnownUsd` is observed model expense on a terminal job without committed billing, not a refund or full loss estimate.

The existing billing idempotency key and lease fencing remain authoritative. The final attempt archive write occurs while the lease token is still held; stale writers and cancelled-state overwrites remain rejected by the existing transaction. At most 32 attempts, 64 transitions and 40 cost stage rows per attempt are retained. Job-level cost totals include older observed attempts even after detail truncation. Archives include no prompts or source text in this trace.

The ledger observer captures outer ledgers once. Worker processes forward each finished logical call as a checkpoint, without treating checkpoints as completed jobs; a queued worker retains the admitting job's observation context. Terminated in-flight calls can have unobserved cost, so coverage is explicitly `observed_ledgers_only`, never complete. Jobs with no observed ledgers keep cost unknown. Checkpoints are persisted with the next existing job state write and on lease completion; a process crash before persistence may lose the latest observations.

`modelCost.stages[].latency` contains logical-call wall time, including retry/backoff, with nearest-rank p50/p95. Calls may overlap, so their summed wall time is not job duration or provider inference time. HTTP attempts, logical calls, known USD, unknown reservations and mandatory audit classification remain separate.

# Offline comparisons and batching

Run `node scripts/audit-quality-benchmark.js <private-input.json> <private-output.json>` outside the repository's tracked data. Input is `{ rows: [...], detectorThreshold?: number }`. Each row needs a unique `id`; cost comparisons additionally use `genre`, `sourceChars`, `outcome`, and `baseline`/`candidate` objects. Both sides must have `qualityPass: true` and the same nonempty `qualityContract`. Optional measurements are `logicalCalls`, `knownUsd`, `unknownReservedUsd`, `queueWaitMs`, `executionWallMs`, `totalWallMs`, and stage rows (`stage`, `calls`, `knownUsd`, `unknownReservedUsd`). Each metric compares only pairs measured on both sides. Output is stratified by genre, text length and outcome; missing measurements remain null.

Detection evaluation requires explicit `independentLabel: true`, nonempty `labelSource`, unique `sourceGroupId`, `workflowLabel` (`human`, `ai`, `mixed`) and `detectorScore` from 0 to 100. Mixed workflows are reported separately. Repeated source groups and missing labels are excluded; the script does not create labels, infer them from model scores, change history correction, or claim population accuracy. Use an independent, consented labelled dataset; the historical audit corpus alone does not supply it.

The existing production `shortChunkBatch` already batches short primary requests by contract and preserves individual validation. Its quota/timeout failure path avoids fan-out retries. `planBatchExperiment` in the offline tool proposes additional grouping only with `enabled: true`; it never calls a model or activates a production path. Explicit editable/unprotected decisions and parent, role and contract boundaries are required. Protected, oversized and unknown blocks flush the group. Production activation of a different grouping requires exact ID coverage and source/candidate/structure/judge/contract validation plus matched quality results. No speed or cost saving is claimed without those measurements.

Existing Korean-only admission and balance prechecks remain before generation; no extra model calls or quota polling are added.
