# 감사 후 전체 품질 보완

엔진 `gpt-prod-v2.5.105`, 전처리 버전 38. 전처리·구조, 후보 추적, 코칭·추천, 의미·장르, 입력 완전성, 운영·비용 관측까지 보완한다. 이력 일치 조건, 점수 보정, 하한·상한, 표시 점수와 전후 비교 정책은 변경하지 않는다.

## 동작

- 셀 구분자가 사라진 평문 표에서 영역·위험요인·개선 과제 헤더와 반복 행을 함께 인식한다. 헤더가 모두 확인된 부분 복사 표도 줄 경계를 보존한다. 열이나 누락 내용을 만들어 넣지 않는다. 같은 인식이 전처리·청크 잠금·관계 digest에 적용돼 셀 병합에 공백 동등 검증을 재사용하지 않는다.
- 긴 미완결 산문의 종결·연결 어미 조각을 문맥으로 구별한다. 인접한 같은 단계의 가나다 목록 증거가 우선하며, 목록이 가부터 시작할 필요는 없다. 짧은 시·명시적 구조·코드는 보호한다.
- 원문 정규화 전후 digest와 변경 구간, 선택 후보 digest·단계·사유·복귀 여부, 최종 검증 대상 digest·상태·허용 변환 종류를 이력과 작업 보관 문서에 저장한다. 후보 원장과 본문은 추가 복제하지 않는다. 필드가 없는 과거 기록은 미확인 상태로 남는다.
- 보고서 제목·등급·문단 안내·코칭은 내용 근거의 축 정책을 공유한다. `off`, `sparse`, `limited`를 결핍으로 바꾸지 않는다. 기존 내부 모드 라우팅과 요금 계산에는 같은 입력을 계속 사용한다.
- 위치가 맞아도 어미·조사만 남은 조각은 문체 재작성 후보에서 제외하고 입력 확인 안내로 분리한다. 실제 문장은 legacy 대상 수와 무관하게 유지한다. 문자열 길이와 위치는 UTF-16 기준이며, 짧은 정상 답변은 일괄 제외하지 않는다.
- 문단 역할과 상황·행동·대상·산출물, 빈도·수량이 있는 계획을 표시용 관찰에 반영한다. `not_assessed`, `not_found`, `present`를 구분한다. 낮은 탐지량만으로 `deficient`를 만들지 않으며 정의·절차·인용에 개인 의견을 요구하지 않는다. 기존 surfaceguard와 점수 산출은 그대로다.
- 추천 후보에는 목적·근거 ID·원문 UTF-16 위치·예상 편집 범위·보호 구간을 연결한다. 코드·인용 전체 및 미완성 꼬리를 문체 후보로 사용하지 않는다. 선택적 기능 접근과 자동 추천은 계속 구분한다.
- 현재 의견 술어가 남은 안전한 1인칭 생략은 화자 삭제로 경고하지 않는다. 합니다체 자체나 타인의 의견은 1인칭 근거가 아니다. 문단의 성찰 귀속·학력 주장 강도·힘의 방향·병렬 관계·인식 시제·명사 호응·지시 대상 변화를 위치 증거와 함께 기존 의미 검사에 전달한다. 후보는 오류 확정이나 자동 단어 교체 지시가 아니다.
- 시의 행·반복·감탄 음성 변경을 확인하고, 행 중심 창작문과 제목만 있는 입력에는 최소 변형량을 요구하지 않는다. 이 장르에서 단순 무변환 때문에 전체 문서 재호출·상위 모델 승격을 하지 않는다. 의미·수치·구조 검사는 유지한다.
- 원문에 없던 인접 중복은 기존 문항·주체·조건·인용 경계를 확인해 의미 검사 후보로 보낸다. 원래 있던 반복과 결론 재확인은 자동 삭제하지 않는다.
- 인용·코드·URL·수식 밖의 명백한 HTML 공백/앰퍼샌드만 한 번 복구하고 정확한 변경 좌표를 기록한다. 잘렸을 수 있는 시작 단어와 미완성 끝·수식 누락을 입력 확인 대상으로 남긴다. 누락 명사·결론·출처·수식의 창작 보충을 금지하는 계약을 공유한다.
- `inputStatus`는 입력 완전성·구조 정규화·의미 검증·문체 효과를 분리한다. `no_issue_detected`는 입력 전체가 완전하다는 인증이 아니다. 사용자 화면에 입력 확인 안내를 별도로 표시한다.
- 실행 lease별 시작/재개/완료/취소·상태 전이·사용자 과금 상태와 관측된 호출 원가를 기록한다. provider abort 요청과 실제 중단 확인을 구분한다. 과금·재시도·lease 정책은 바꾸지 않는다. 취소·미리보기 완료·관찰 시 미완료의 분모를 분리한다.
- 단계별 논리 호출 수·HTTP 시도 수·확인 원가·미확인 예약 원가와 호출 지연 p50/p95를 보존한다. 호출 지연은 재시도/대기를 포함하며 병렬 합계는 전체 처리 시간이나 순수 추론 시간이 아니다.

## 추가 메타데이터

| 필드 | 내용 |
|---|---|
| `sourceNormalization` | 제출·정규화·무결성 기준 원문의 SHA256, 변경 여부, 변경 전체를 포함하는 UTF-16 구간 |
| `candidateLedgerSelectedDigest` 및 `candidateLedger*` 요약 | 선택 단계·사유·복귀 여부·개수. 선택 이후 허용 편집이 있을 수 있어 반환 해시와 무조건 같은 값으로 간주하지 않는다 |
| `finalValidationReceipt` | 실제 반환 해시, 검증 대상 해시, `exact`/`whitespace_layout`, 최종 확인 상태와 부모 검증 해시 |
| `reportView.conversion.candidatePolicyVersion` | `candidate-editability-v2-contract` |
| `reportView.conversion.inputReview` | 조각 확인 안내와 제한된 위치 목록. 점수 변경 근거가 아님 |
| `contentAssessmentStatus` | 내용 근거 평가 상태. 미평가일 때 `grade`와 공개 `abstractRiskRatio`는 null |
| `contentEvidence.findingStatus`, `contentContexts` | 탐지 실패와 실제 결핍을 구분하는 표시 정책·문단 역할 |
| `conversion.targets` | 근거 ID·위치·목적·예상 범위·보호 영역. 제한된 목록과 전체 개수를 구분 |
| `inputStatus`, `encodingNormalization` | 입력 상태 및 엔티티 복구 좌표·SHA256. 텍스트 추가 저장 없음 |
| `attemptLifecycle` | 보관 문서의 실행 시도·전이·과금 상태·관측 원가. 누락된 과거 기록은 미확인 |
| `modelCost.stages[].latency` | 논리 호출 지연 표본 수·p50/p95·합계 |

`sourceNormalization.changeRange`는 여러 편집을 포함하는 외곽 구간이다. 편집마다 일대일 위치가 복원됐다는 뜻이 아니다. 구조 판단과 어미 판단은 제한적인 결정론 규칙이며 새로운 전체 의미 검증을 대신하지 않는다.

## 검수

합성 fixture로 표·부분 목록·시·코드·공백 동등 관계, 원장 저장 및 보관 왕복, 정상 후보와 입력 조각, 코칭 평가 상태를 검사한다. 고정된 서명 이력과 설정에서 62→37, 18→11, 10→10 및 비교 정책을 회귀시험한다. API 시험은 로컬 provider·과금 대역을 사용한다.

사용자 자료의 로컬 재검증 결과와 실행 로그는 저장소 밖 보고서 폴더에 보관한다. 검증되지 않은 변경을 배포하거나 이 문서를 배포 완료 근거로 사용하지 않는다.

## 비용·분류 평가

기존 ID 기반 짧은 청크 배칭과 요청 내 엄격한 검증 영수증을 유지한다. 검증 키는 원문·후보·구조·주변 문맥·판정기·보존 계약을 포함하며 새로운 입력/의미 정책 파일도 fingerprint에 넣는다. 시·제목의 변형량 재시도 제거는 품질 검사를 끄지 않고 불필요한 호출 경로를 줄이는 변경이다.

`node scripts/audit-quality-benchmark.js <input.json> <output.json>`은 외부 API 호출 없는 비교 도구다. 같은 qualityContract에서 양쪽 qualityPass가 명시적으로 참인 대응 표본만 비용/시간을 비교한다. 장르·길이·완료 상태별로 묶고 대기/실행/전체 시간을 분리한다. 독립 작성 흐름 라벨·출처·sourceGroupId가 없는 자료나 종속 중복은 감지 오류율에서 제외한다. 현재 감사 사례를 정답 라벨로 사용하지 않는다.

`planBatchExperiment`는 명시적으로 켠 오프라인 실험 계획만 만들며, 보호 여부/계약/부모 ID가 불명확하면 묶지 않는다. 실제 모델의 절감률·정확도 향상은 이 코드와 로컬 대역 시험만으로 입증하지 않는다. 별도 실측·독립 라벨 없이 수치를 만들어 보고하지 않는다.
