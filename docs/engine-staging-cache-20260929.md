# 장문 심사 순서·정확 계산 재사용 구현 기록

기준: 운영 c863be8 / gpt-prod-v2.5.89. 별도 기능 worktree에서 이전 미배포 후보 a54654f를 가져와 수정했다. 운영 설정·모델·추론 강도·과금은 변경하지 않았다.

## 확인된 원인

1. 한국어 검사·지문·편집 깊이·관계 검사가 같은 문자열 쌍의 편집거리를 반복 계산한다.
2. 첫 심사에서 오류가 발생한 구간도 약한 심사 모델로 수리·재심사를 마친 뒤, 마지막에 처음 강한 확인을 받는다. 뒤늦게 발견된 오류를 고치고 검증할 여유가 줄어든다.
3. 앞 단계 3개 제목 구간과 마지막 2개 길이 구간이 달라져 기존 판정의 정확한 재사용이 어려워진다.
4. 복구 시간 제한은 복구 시작이 아니라 작업 초반부터 계산된다. 측정한 장문은 첫 의미 심사가 400초 이후여서, 일반 선택적 추가 확인은 180초 예약 경계에 이미 걸릴 수 있다. 이번에 한도를 확대하지 않았다.

## 구현

### 정확 계산 재사용

- 외부 요청·전역 저장소 없이 현재 최상위 요청 안에서만 편집거리 계산을 재사용한다.
- 문자열 강제변환·순서·유니코드 처리를 기존과 동일하게 유지한다. 근사값이나 정규화된 다른 문자열의 값을 재사용하지 않는다.
- 최대 8,192쌍·키 1,000,000문자, 50,000자를 넘는 쌍은 저장하지 않는다. 오래된 항목을 제거하고 요청 종료·오류 후 저장된 문자열을 해제한다.
- 관측값은 호출·적중·상한 등 숫자만 반환한다. 원문을 운영 로그에 추가하지 않는다.

### 실험적 단계형 확인

- `HUMANIZE_STAGED_CONFIRMATION_ENABLED=1`일 때만 실행한다. 기본값은 OFF다.
- 2~4개 제목 구간을 안전하게 대응할 수 있고, 요청 내부 판정 저장소가 있을 때만 해당한다.
- 확인이 필요한 1차 실패는 수리 전에 기존 확인 모델로 넘기는 경로를 추가했다. 정확한 누락만 있는 경우의 기존 복원 경로는 유지한다.
- 조립 완료된 본문의 추가 확인은 기존 복구 비용·호출·시간 한도 안에서만 수행한다.
- 재사용은 동일 원문·결과·양옆 문맥·질문·모델/추론 정책의 완료된 판정으로 제한한다. 낮은 등급의 통과를 높은 등급 판정으로 바꾸지 않는다.
- 불확실한 수리 결과를 본문으로 채택하지 않는다. 추가 확인 상태만으로 최종 검증을 생략하지 않는다.

## 검증 범위와 제한

- 최근 저장된 휴머나이징 60쌍으로 한국어 검사·지문·편집 깊이·관계 검사의 캐시 전후 반환값이 모두 일치했다. 모델을 다시 생성한 시험이 아니다.
- 대표 장문 모듈 재생에서 편집거리 8,489회 중 4,810회(56.7%)를 정확히 재사용했다. 저장 3,679쌍·438,420문자·상한 퇴출 0건이었다.
- 로컬 처리시간은 다른 테스트 실행과 JIT 영향으로 흔들렸다. 적중률을 운영 응답시간 개선률로 발표하지 않는다.
- 실제 문서 전체에서 단계 변경이 호출·비용·시간을 줄인다는 증거는 아직 없다. 추가 확인 뒤 본문이 바뀌면 최종 심사가 다시 필요해져 오히려 호출이 늘 수 있다.
- 기존 장문 전체 실호출 및 최종 심사 미완료 기록을 신규 합격으로 바꾸지 않는다. 새 경로는 전체 재생성·최종 심사 통과 전 활성화하지 않는다.

## 협업

실제 Claude Opus 5.5가 심사 순서 변경을 구현하고, Claude Fable 5.1이 정확 계산 재사용을 구현했다. 양쪽이 코드를 교차 검토했다. Root는 라우팅·회귀 테스트·비공개 60쌍 재생·통합 검증을 수행했다. 검토 중 발견한 후보 복귀 및 심사 상태 유실 문제를 별도 수정 대상으로 처리했다. 협업 모델의 답변 자체를 검증 합격 근거로 사용하지 않았다.

### 판정

정확 계산 재사용의 결과 동일성 및 새 경로의 실패 안전장치는 통과했다. 그러나 심사 시점 변경만으로 출력 한도 문제를 해소하지 못했다. 처리시간·비용·품질이 개선됐다는 운영 성과를 주장하지 않으며, 단계형 확인은 OFF로 보존하고 통합 배포하지 않는다.

다음 미해결 항목은 본문 길이만이 아니라 질문·기존 지적·교차 관계에 따른 심사 작업량 분할이다. 분할 후에는 구간 간 관계와 전체 검증 범위를 빠짐없이 다시 합치는 계약이 필요하다. 질문을 지우거나 추론 강도를 낮추거나 출력 상한을 무작정 늘리는 것으로 통과시키지 않는다. 이전 장문 전체 재생성 미완료 조건도 그대로 남는다.
