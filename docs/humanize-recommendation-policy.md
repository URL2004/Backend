# 휴머나이징 추천 v2

`humanize-recommendation-v2`는 무료 `/diagnose`와 유료 `/detect-report`가 같은 추천기를 사용한다. 생성 모델·변환 강도·과금 공식·고급 사용 가능 여부는 변경하지 않는다.

## 기준

- 고급 미지원 입력은 추천 모드를 비운다. 기존 선택 잠금은 유지한다.
- 편집 가능한 본문이 120자 미만 또는 2문장 미만이면 기본을 우선한다.
- 엔진 계획상 효과가 제한적인 글은 기본을 우선한다.
- 분류기가 미확정(`unknown`, 신뢰도 0.55 미만)인 경우 추천 배지를 표시하지 않고 선택 안내를 제공한다. 위의 본문·효과 기준이 명확하면 그 기준을 먼저 사용한다.
- 학생 기록·지원서·개인 에세이·창작물의 본 장르 또는 안전 보조 장르가 있으면 기본을 우선한다. 고급 선택은 허용한다.
- 기존 고신뢰 논문·보고서와 장문/복잡한 구조 조합은 고급 추천을 유지한다. 위 보호 기준이 우선한다.
- 긴 설명문: 신뢰도 0.75 이상, 전체 2,000자 이상, 편집 본문 1,200자 이상·6문장 이상, 수정 대상 3문장 이상·25% 이상, 엔진 필요도 중간 이상이면 고급.
- 넓은 재구성: 같은 길이·본문 조건에 대상 문단 2개 이상, 대상 문장 6개 이상·50% 이상, 엔진 필요도 높음이면 고급.
- 비용 차이가 작은 장문: 5,000자 이상·고급 추가 30크레딧 이하, 위 본문·문단 조건, 대상 4문장 이상·25% 이상, 필요도 중간 이상이면 고급 후보.
- 마지막 두 경로는 논문·보고서·설명문·일반 글·후기·마케팅만 허용한다. 일반 글·후기·마케팅은 분류기 확정 기준 0.55, 나머지는 0.75를 적용한다. 사실·화자 보호 신호가 우선한다. 비용 또는 추상성 등급만으로 고급을 추천하지 않는다.
- 나머지는 기본 추천과 사유를 제공한다.

전체·본문 길이는 공백 포함이다. 기존 구조 판정의 `formatProfile.length`는 공백 제외 1,500자 기준을 그대로 사용한다. 본문은 엔진 청커가 보호하는 구간을 제외하며, 바깥 파이프가 없는 구분자 표 행도 보수적으로 제외한다. 청크 분할 때문에 문단 수가 늘어나지 않도록 원문 구분자를 보존한다.

## 응답·관측

`recommendedMode`는 `blog`, `formal`, `null`이다. 기본 실행 설정과 강한 추천을 분리한다. `recommendationCode`, `recommendationReason`, `recommendationVersion`, `recommendationSignals`를 두 진입 경로에 제공한다. 신호에는 길이·수정 대상 문장/문단 수·대상 비율·필요도·효과 제한·기본 대비 추가 크레딧만 포함하며 원문은 넣지 않는다.

무료 진단 완료와 유료 감지 완료 로그에 추천 정보를 기록한다. 프런트는 사유를 텍스트로 렌더링하고, 노출·모드 선택 이벤트에 추천 모드·사유 코드·버전·추가 크레딧을 함께 기록한다. 진단 실패 시 이전 사유와 배지를 지운다. 기존 유료 감지의 멱등 재응답은 저장된 추천 버전을 유지한다.

## 검증 및 해석

9월 8~15일 저장 입력 1,207건의 결정론 재실행에서 고급 추천은 64→85건. 긴 설명문 28건, 후기 1건, 일반 글 1건을 추가했다. 기존 고급 중 개인 보존 신호 8건과 효과 제한 1건은 기본으로 조정했다. 짧은 입력의 신규 고급 추천과 고급 사용 가능 여부 변경은 0건이다.

이 수치는 저장 입력 집합의 정책 비교이며 무료 진단 전체의 비율과 분모가 다르다. 같은 입력에서 생성 결과를 비교한 품질 실험이 아니므로 고급 품질 우위나 전환 상승을 주장하지 않는다. 운영 노출·선택 및 결과 품질을 관찰해 조정한다.
