# v2.5.63 — 라벨 본문 문단화와 구조 복원 충돌 수정

작성일: 2026-09-20. 기준: v2.5.62 / 7e491f1.

## 확인한 원인

- 여러 `라벨: 본문` 행이 있으면 본문 길이와 무관하게 가독성 검사에서 제외됐다.
- 일반 산문 문단화는 `prose`만 대상으로 하므로 긴 `label_inline` 본문을 처리하지 못했다.
- 구조 복원과 감사는 라벨 본문의 모든 추가 줄바꿈을 오류로 취급했다. 단독 문단화 수정만으로는 마지막 복원에서 다시 붙을 수 있었다.

## 수정

- 짧은 라벨 묶음 면제는 유지하되, 개별 본문이 길면 검사 대상으로 삼는다.
- 기본·고급의 서버 소유 최종 레이아웃 단계에서 라벨 접두부와 본문을 분리해 처리한다. 본문은 기존 산문 분할과 완결 문장 사이의 전환·길이 조건을 사용한다.
- 각 분할 단위가 최소 두 문장인 완결 산문일 때만 허용한다. 문장 중간의 줄바꿈은 여전히 오류로 복원한다.
- 구조 복원과 구조 감사가 같은 안전성 판정을 사용한다. 최종 반환 텍스트에도 라벨 구조 감사를 수행한다.
- 긴 인접 라벨 항목 사이의 시각 여백 및 콜론 뒤 공백을 보완한다.
- 단어·수식·수치 변경 없이 공백만 조정한다. 인용 내부·코드 분할은 허용하지 않는다. 다듬기, 보존 계약, 승인 구조, 법률·창작·임상 기록, 전체 행 잠금은 이번 새 문단화 대상에서 제외한다.
- 모델·프롬프트·요금·차단 정책 변경 및 추가 API 호출은 없다.
