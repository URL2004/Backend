# PDF 평문 추출 무결성 수정 · 2026-09-25

## 확인한 원인

- 브라우저가 PDF.js의 TextItem 좌표와 줄 경계를 버리고 페이지 전체를 공백으로 연결했다. 글자 조각 사이에 불필요한 공백이 생기고, PDF 내부 그리기 순서가 그대로 읽기 순서가 됐다.
- 서버의 기존 페이지 추출 복구는 로마 숫자 목차·참고문헌 등 일부 학술 양식을 전제로 했다. 숫자 목차의 일반 보고서는 연속 페이지와 반복 공백이 충분해도 복구 대상에서 빠졌다.
- 이후 생성/폴백 경로의 공백 처리가 달라 결과 일부에만 추출 공백이 남았다.
- 구조 서명은 입력된 텍스트와 결과의 비교다. 서버에 없는 원본 PDF의 행·열 대응 관계를 검증하지 않는다.

## 변경

1. 프런트 별도 변경에서 좌표 기반 물리적 행 복원, 확인되는 열 경계 탭 보존, 페이지 간 임의 문장 결합 금지, 불확실한 추출 순서 안내를 적용한다.
2. 서버는 연속 3쪽 이상 + 긴 산문 2쪽 이상 + 페이지별 30개 이상의 반복 공백 + 보고서류 제목이 함께 확인될 때 숫자 목차 문서도 공백 복구 대상으로 삼는다. 일반 목록·비연속 페이지·코드·탭 표는 기존 제외 기준을 유지한다.
3. 페이지 다음에 새 제목이 있어도 앞 페이지가 미완성일 수 있다는 경고를 누락하지 않는다. 알려지지 않은 단어·셀 연결을 추측하지 않는다.
4. 문자 내용·순서 불변 검사, 인용·URL·표 탭 보존, 재적용 멱등성을 검증한다.
5. `structureAuditScope=submitted_text`, `sourceLayoutStatus=reading_order_unverified|text_only`를 기록·아카이브·관리자 응답에 전달한다. PDF 읽기 순서 미확인 입력은 검토 안내를 유지한다. 새 차단·과금 정책은 추가하지 않는다.

## 검증

- 백엔드 1,964개 테스트 통과. 모의 모델 통합 테스트 포함(실제 모델 품질 성과 아님).
- production import graph 위반 0건.
- 합성 2쪽 PDF를 운영과 같은 PDF.js 3.11.174로 읽어 좌우 열의 그리기 순서가 뒤바뀐 표 3행의 대응을 확인했다. 프런트 추출 → 서버 전처리 뒤에도 열 구분이 유지됐다.
- 개인 자료는 커밋하지 않는다. 원문·결과·식별자·운영 계정·실호출 자격증명은 이 문서에 포함하지 않는다.

## 남은 제한 / 출시 조건

- PDF 원본이 보관되지 않은 과거 작업은 원래 행·열·페이지 소유권을 확정할 수 없다. 과거 결과 자동 수정 또는 임의 재구성은 하지 않는다.
- 이미지 OCR, 회전·세로쓰기, 복잡한 병합 셀, 페이지를 넘는 논리적 행 재결합을 해결 완료로 주장하지 않는다. 좌표 추출은 물리적 행을 보존하며 논리적 행 병합을 추측하지 않는다.
- 실제 모델 재실행, 원본 없는 사례의 최종 의미 품질, 처리시간 단축은 아직 검증되지 않았다. 사용자에게 이 제한을 설명한 뒤 2026-09-25 배포 지시를 받았다. 이번 배포는 로컬 무결성·합성 PDF 검증을 통과한 수정이며, 신규 유료 모델 검증 완료로 발표하지 않는다.
- 출시 버전은 v2.5.67이다. 과거 작업·크레딧은 수정하지 않는다. 실제 배포 완료 시각과 커밋은 별도 운영 영수증에 기록한다.
