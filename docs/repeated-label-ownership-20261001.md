# 반복 출처·인용·소제목 경계의 통합 복원

기준: production `2df11d4`, engine `gpt-prod-v2.5.95`.
사용자 원문·결과·식별자와 로컬 실행 자료는 저장소에 포함하지 않는다.

## 원인

문장 분할 전체의 고장이 아니라 원문의 서로 다른 구조 구간을 같은 문자열로 식별한 후처리 결함이다. 모델 없이 원문 그대로 실행해도 재현했다.

1. 라벨 본문 복원은 원문의 독립행 라벨을 결과 전체의 첫 접두부와 대응시켰다. 앞선 인라인 출처가 선택되면서 다음 소제목·본문의 개행까지 지웠다. 잠긴 라벨 복원에도 같은 문제가 있었다. 독립행 출처는 단계별로 10→14→5개가 됐다.
2. 이 두 문제만 고치면 소제목은 살아나지만 문단 정리기가 출처 안의 `7.3.2.`를 문장 끝처럼 분리했다. 여러 후처리가 경계를 넣고 지우며 수렴하지 않았다.
3. 인용 정규식은 여러 줄 정상 인용과 닫는 자리에 여는 곡선 따옴표를 쓴 후보를 놓쳤다. 정상 인용은 1→0으로 오인했고, 형식 불확정 후보는 내용이 변해도 0→0으로 통과할 수 있었다.
4. 최종 레이아웃의 `pass`는 후속 변경 전 스냅샷을 사용했고 수렴 여부도 검사하지 않았다.

`blog`→`assignment` 라우팅은 이 병합의 필요조건이 아니다. 모델 실패 0, 승인 청크 수, `deliver_review`도 구조·인용 통과를 뜻하지 않는다.

## 구현

- 반복 라벨은 인라인 출현까지 포함한 원문 순번·개수와 검증된 청크 위치로 대응한다. 불확실하면 전역 첫 매치로 돌아가지 않고, 후속 구조행을 소비하지 않는다.
- `citationOwnership.js`는 원문 절·순번·전체 출처 리터럴·쪽수·인라인/독립행 관계를 보존한다. 문장 분할은 출처 내부 경계를 후보에서 제외한다.
- 출처 내용 복원과 공백 복원을 분리했다. 내용 복원은 절 내 접두부 개수, 순서, 전체 쪽수열, 다음 원문 앵커까지의 빈 구간과 경쟁 후보를 검사한다. 새 본문 문장이 끼면 거부한다. 누락·추가·이동을 임의의 순번으로 보충하지 않는다.
- `quoteOwnership.js`는 소제목·출처·코드·표 경계를 넘지 않는 인용 후보를 식별한다. 여러 줄 인용을 세고 형식 불확정 후보의 내용도 검사한다. 기존 인용이 이동했을 때 다른 인용으로 덮어쓰는 복원을 거부한다.
- `sourceLiteralRecovery.js`는 내용 복원을 레이아웃 전에 수행한다. 인용부호까지 사라진 경우에는 원문 절 본문이 인용 하나와 바로 뒤 출처로만 구성되고 양쪽 앵커가 확인될 때만 그 구간을 복원한다. 원문과 결과 모두 출처 뒤에 별도 서술이 없어야 하며, 기존 인용·짧은 용어·책 제목이 이동한 경우도 거부한다. 인용이 이미 존재하거나 소제목 안에 있으면 새 복원 구간으로 사용하지 않는다.
- 출처와 이에 직접 연결된 인용은 모델 청크 단계부터 잠근다. 나머지 본문은 편집 가능하다. 따옴표나 중복 출처를 자동 삭제하지 않는다.
- 코드·수식 토큰을 풀어 쓴 청크에는 실제 원문 레이아웃 좌표를 별도로 둔다. 원래 청크 ID·마스킹 좌표는 유지한다.
- 마지막 반환 문서의 구조·출처를 다시 검사하고 수렴을 통과 조건에 포함한다. 운영 후처리와 늦은 후보 재검증에 같은 복원 순서를 연결했다.

## 실제 저장 문서 재생

서버 원문 9,538자와 기존 결과 9,521자를 로컬에서 결정론적으로 재생했다. 원본 PDF와 대조한 결과는 아니다.

| 확인 항목 | 통합 수정 후 |
| --- | --- |
| 소제목 독립 경계 | 보존 |
| 출처 전체 출현 | 22개 보존 |
| 출처 독립행 | 원문과 같은 10개 |
| 원문 인용 후보 | 12개 보존, 형식 불확정 후보 7개 포함 |
| 바뀐 출처 내용 | 원문 앵커로 확정한 3개 구간 복원 |
| 최종 구조·출처·인용 감사 | 통과 |
| 전체 후처리 수렴 | 2회 |
| 재실행 결과 | 동일, 재실행은 1회에 수렴 |
| 원문 그대로 재생 | 구조·인용 보존 및 수렴 통과 |

직접인용 후보는 원문의 내용·기호·내부 공백을 보존하므로 그 안의 자연화는 유지하지 않는다. 인용 밖의 문장 개선까지 문서 전체 원문으로 되돌리는 처리는 하지 않는다.

## 공동 검토와 검사

실제 Claude Code의 `claude-fable-5-1`, `claude-opus-5-5` 모델 식별자를 확인했다. 두 모델이 설계를 교차 검토하고 각각 출처·인용 모듈을 구현했다. 부모 작업에서 통합·실제 문서 재생·테스트를 수행했다. 임의의 순환 상태 고정, 전역 유사도에 따른 인용 덮어쓰기, 원문 전체 동일성을 가독성 조건으로 삼는 제안은 채택하지 않았다.

합성 회귀는 반복 출처, 내부 절 번호, 소제목 접합, 인용부호 누락, 여러 줄·형식 불확정 인용, 이동·누락·추가, 본문 침범 거부, CRLF·보조평면 문자·마스킹 좌표, 코드·표 제외, 재실행 안정성을 검증한다. 기존 합성 검사에서 탭 열 손실이 중간 통과값에 가려지던 사례는 최종 감사 실패를 요구하도록 강화했다.

마지막 교차 검토에서 발견한 뒤쪽 본문 침범, 기존 인용 중복, 소제목 안 인용의 오복원, 짧은 용어·책 제목 삭제, 모델의 청크 공백 제거 반례를 추가하고 차단했다. 전체 전달 조합(내용 복원→최종 레이아웃→전달 직전 복원)을 두 번 실행해 동일성을 확인했다. 전달 직전 복원은 이미 정리된 가독성 빈 줄을 다시 원문 간격으로 되돌리지 않는다.

최종 전체 회귀 **2,893개 통과**. 운영 import 검사 **283개 파일, 위반 0**. `git diff --check` 통과. 인용이 많은 문서의 대응 계산에도 메모리 상한을 적용했다.

복원 결과의 출처·인용 통과값은 반환하는 최종 문자열에서 계산한다. 복원 거부 횟수와 각 인용 구간의 복원 전후 문자 수를 원문 문자열 없이 기록한다. 다른 절의 미확정 인용 때문에 안전하게 복원할 수 있는 절까지 포기하지 않되, 부분 복원 후 남은 실패는 그대로 보고한다.

## 범위

원문이 직접인용인지 간접인용인지의 저작 의도를 추측하거나 원본 교재/PDF의 정확성을 인증하지 않는다. 원문 미닫힘 기호는 보존하고 기존 원문 검토 알림을 유지한다. 복원 근거가 불확실하면 감사 실패를 남긴다. 수정 버전은 `gpt-prod-v2.5.96`이다. 사용자 승인에 따라 이 변경을 운영 배포 대상으로 준비했다. 실제 배포 성공 여부는 배포 서비스의 커밋과 운영 상태 응답으로 별도 확인한다.
