## 수정

- 상위 심사 후 복구한 구간은 같은 상위 심사 수준으로 재검증한다. 하위 판정으로 실패를 덮지 않는다.
- 원문 그대로인 문장 복원이 반복 문체 경고의 개수 문턱을 활성화했을 때, 이미 있던 다른 문장을 신규 결함으로 잘못 계산하지 않는다. 상대 비교에서만 원인을 구별하며 문서 자체 경고는 유지한다. 새 표현과 중복 복사 검사는 유지한다.
- 재심사가 그대로 남은 다른 문단의 기존 오류를 새로 발견해도, 검증된 국소 복구를 모두 폐기하지 않는다. 같은 문단·인접 문맥·구조/인용 소속, 양쪽 재접지 및 모든 이전 지적 처리를 요구한다. 잔여 지적과 실패 판정은 유지한다.
- 전체 수리본의 거절 코드가 최종 심사 보고서 교체로 사라지지 않도록 선택 메타 필드 `semanticRepairFullDocumentRejectCodes`에 코드만 남긴다. 원문·결과·사용자 식별자는 복제하지 않는다.
- 마지막 실호출에서 남은 의향/희망 교환과 조건절의 반복 표현 추가를 초기 의미 심사의 명시적 검토 질문으로 연결한다. 자동 오류 확정이나 자동 문장 교체는 하지 않는다. 이미 문맥에 반복이 함의된 경우 등은 정상 판정할 수 있다.
- 새 후보 분석의 보호 구간은 문서마다 감사 호출 안에서 한 번만 지연 계산한다. 반복 표지마다 전체 문서를 다시 분석하지 않으며 전역에 원문을 보관하지 않는다.

## 예산 및 남은 출시 조건

최종 심사에서 처음 지적된 의향/희망 관계 변화와 반복을 뜻하는 부사 추가의 조건 변화가 남는다. 앞선 심사에서는 검출되지 않았으며 최종 심사를 마친 뒤에는 승인된 복구·재검증 시간 창이 부족했다. 이 지적을 억제하거나 미검증 수리본을 통과로 표시하지 않는다.

이후 비용 없는 원인 대조에서 두 표현이 최초 심사의 후보 목록에도 없었음을 확인했다. 마지막 후보 규칙 수정 후에는 저장된 최초 심사 입력과 최종 두 구절 모두 명시적 검토 질문이 생성된다. 인용·코드·다른 술어·기존 반복·정상 문장 합치기 반례도 검사했다. **이 마지막 규칙 수정은 아직 유료 생성·복구·최종 심사로 재검증하지 않았다.** 앞선 실호출 성공 항목을 마지막 수정본 전체의 실호출 통과로 해석하면 안 된다.

따라서 운영 배포는 하지 않는다. 두 항목의 앞단 검출·복구와 최종 검증 완료가 출시 조건이며, 현재 후보는 검증 가능한 코드와 합성 회귀 사례로 보존한다. 모델·요금·과금·전달 정책 및 최종 심사 제한시간은 바꾸지 않았다. 실제 원문과 모델 응답은 저장소 밖 비공개 자료에만 보관한다.

후보 추가는 새 재시도 루프나 상한 확대가 아니다. 다만 기존 정책 안에서 검토 대상 증가에 따른 출력 토큰 예약 증가, 미확정 답변에 따른 기존 상위 심사 경로 진입이 가능하다. 따라서 비용·호출 수가 반드시 같다고 주장하지 않으며 마지막 실호출에서 확인해야 한다.
