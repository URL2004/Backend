# v2.5.80 — 구조 복원 좌표 무결성 수정

검증일: 2026-09-27. 기준 운영 커밋: `9680188` / v2.5.79.

## 확인된 원인

1. `structureChunk.findWhitespaceEquivalentSpans`가 원문 위치표를 Unicode 코드포인트 단위로 만들면서 검색 결과에는 JavaScript UTF-16 인덱스를 사용했다. 이모지·보조 평면 문자 뒤의 위치가 어긋나 라벨, 제목, 표 행의 일부를 다른 위치에 덮어썼다. 끝 위치가 없으면 잘못된 slice가 문서를 재삽입할 수 있었다. 고정점 복원을 반복할수록 파편과 중복이 늘어났다.
2. `voiceProfile.findUniqueNormalizedEvidenceSpan`에도 같은 좌표 단위 불일치가 있었다. 보조 평면 문자가 있는 인용 근거의 정확한 위치를 보장하지 못했다.
3. 물리적 줄바꿈으로 끊긴 한국어 종결어미의 `다.`를 가나다 목록 접두부로 잠갔다. 복원 시 앞선 정상 문장의 `다.`를 찾으면서 새로운 단어 잘림까지 만들었다. 이미 문서에서 확인되는 단어의 뒷부분을 소제목으로 오인하는 경로도 있었다.

이는 PDF 업로드 전용 문제가 아니다. 추출 흔적이 있는 텍스트 입력에서도 재현된다. 운영 사고 기록에는 구조 실패와 의미 불확실 경고가 저장되어 있었으며, 기존 검토 전달 정책에 따라 결과가 전달된 상태였다.

## 수정

- 정규화 문자열의 **모든 UTF-16 코드 단위**에 원문 시작·끝 위치를 기록한다.
- 교체 전 좌표 범위와 해당 원문 조각의 정규화 동등성을 재검증한다. 유효하지 않은 위치를 추측하여 교체하지 않는다.
- 인용 복원에도 같은 좌표·근거 검증을 적용한다.
- 인접 행 사이의 명확한 종결어미 또는 문서 내에 이미 나타난 단어 연결 증거를 공유한다. 해당 행을 가짜 목록/제목으로 만들거나 접두부로 분리하지 않는다.
- 실제 가나다 목록, 빈 줄을 사이에 둔 별도 항목, 코드, 표, 메타데이터는 보호한다.
- 모델, 프롬프트, 요금, 전달·차감 정책, 감지 점수 정책은 변경하지 않는다. 추가 모델 호출을 넣지 않는다.

## 검증 한계 및 운영 반영

- 이 사례의 새 유료 모델 전체 재생성은 아직 수행하지 않았다. 이번 결함은 모델을 호출하지 않고 실제 원문 그대로도 발생하는 결정적 복원 결함이며, 동일 입력으로 수정 전후 재현을 확인했다. 통합 테스트의 모델 응답은 모의 응답이다.

- 기존에 저장된 손상 결과를 자동 수정하거나 재과금하지 않는다.
- 운영의 진행 중·대기 작업이 모두 0인 시점에 배포하고, Render의 배포 커밋과 `/healthz`, 상세 health의 엔진 버전·복원 준비 상태를 확인한다. 신규 구조 손상이 확인되면 기준 운영 커밋으로 복귀한다.
