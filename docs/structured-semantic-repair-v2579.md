# v2.5.79 — 구조 ON 의미 수리 보존

2026-09-27. 기준 후보 `2a4c315`(v2.5.78, 미배포). 비공개 원문·결과·유료 실행기는 저장소 밖에서 관리한다. 상태: 배포 요청은 승인되었으나 **최신 통합본의 전체 재생성 검증 미완료로 보류**.

## 원인 (v2.5.78 추가 3,000원 실행의 저장 응답을 같은 코드로 무료 재생해 확정, 최종 출력 일치)

1. **표지 부제가 본문으로 분류됨.** `제목` / `: 부제` 두 행이 prose로 판정되어 구조 계획 적용 시 한 행으로 합쳐지고, 잠금은 `제목 : ` 라벨에만 걸려 부제가 재작성됐다. 이 행 기준점 결함(손실 1·원문 기준 손실 1·추가 1)이 이후 모든 구조 검사에 남았다.
2. **절대 구조 게이트가 무관한 수리까지 폐기.** 1차 의미 심사는 위반 10건을 찾아 4개 문단을 수리했다. 수리본의 구조 결함은 수리 전 글과 정확히 같은 3개(신규 0)였지만 `full_document_structure_loss`로 통째 거절됐다. 최종 심사의 잔여 지적은 이 버려진 수리의 잔여다.
3. **최종 관계 복원이 긴 문서에서 실행 불가.** 조건이 `남은 시간 ≥ 1.2 × 최종 심사 시간`(120초 창)이라 심사가 54.5초를 넘으면 시도되지 않는다. 10,312자 실측 66.8초.
4. **건너뛴 이유 미기록.** `finalRelationRestorationAttempted=false`만 남았다.

## 수정

- `layoutStructure`: 표지 제목(시작 행 또는 제목·머리말 바로 뒤의 명사형 행)과 바로 붙은 `:` 명사형 부제 행을 title로 판정한다. 문장·라벨·목록·본문 뒤의 행은 제외한다.
- `structureChunk.structureAuditNotWorseThan`, `preservesFinalStructure(..., { current })`: 후보가 절대 검사에 실패해도 current가 이미 실패했고, 후보의 결함이 내용 기준 multiset(위치 필드 제외)으로 모두 current에 있던 것이면 허용한다. 개수 증가, 통과하던 차원의 실패, 결함 바꿔치기는 거절한다. 의미 수리 검증, 결정론 관계 복원, 최종 관계 복원에만 연결했다. 전달 직전 절대 구조 검사와 안전 후보 롤백은 그대로다.
- `repairBlockAdoption`: 문서 전체 의미 수리본이 거절되면, 문단 경계가 같을 때 문단별로 같은 검증을 통과한 수리만 채택한다. 조합은 원래 입력 기준으로 다시 검증하며 검증 완료로 표시하지 않는다(최종 재검증이 다시 판정).
- 최종 재검증 직전에 앞선 판정의 정확한 쌍 복원(`restoreConfirmedRelations`)을 적용해, 추가 모델 호출 없이 한 번의 최종 판정으로 검증한다. 기존 판정 후 복원 경로는 유지한다.
- `certaintyEndingRestore`: 원문이 `N(으)로 볼 수 있다`, `N(이)라고/라 할 수 있다`, `V다고 할 수 있다`로 끝나고 대응 결과 문장이 같은 수식어+서술어의 단정으로 끝나면 서술어 끝만 원문 표지로 되돌린다. 대응은 유사도 0.35 이상과 2위·경쟁 원문 대비 0.08 여유로 확인하며, 원문에 같은 서술어의 단정 문장이 더 가까우면 하지 않는다. 인용·코드 안은 제외한다.
- `relationAudit` v9: 해석 표지가 사라지고 인과 표지가 생긴 문장, `N보다 → N이 아니라`를 심사 후보로 추천한다(후보일 뿐 차단 아님, `무엇보다`·`누구보다` 제외).
- engineMeta: `semanticRepairPartialAdoption*`, `preFinalRelationRestoredCount`/`SkipReason`, `finalRelationRestoreSkipReason`, `certaintyEndingRestoreCount`.

모델·추론 설정·요금·전달 정책·감지 점수 변경 없음. 구조 계획 버전(`document-structure-v3`)은 저장된 계획 만료를 피하려고 유지한다.

## 남은 한계

- 판정 모델은 양보→충분조건 부정 같은 범위 변화를 통과시킬 수 있다. 결정론 후보는 비교→배제와 해석→인과만 보강했다.
- 판정 전 복원은 문장 전체를 원문으로 되돌리므로 휴머나이징 깊이가 낮아질 수 있다. 판단 표지 유형은 서술어 끝 복원이 먼저 적용되어 이를 줄인다.
- 추출 과정에서 구분자가 사라진 인라인 라벨(`배경`, `상징`, `캐릭터`, `작가주의`)은 회차마다 본문 흡수 또는 구분자 추가로 달리 처리됐다. 목차 `미 래`, `정 리 하는 말` 등 입력 손상과 캡션 사실은 외부 근거 없이 고치지 않는다.
- 표본은 한 문서 세 번의 생성이다. 모든 문서의 무오류 보장이 아니며, 원본 PDF 좌표·그림 위치는 검증하지 않았다.

## 배포

배포하지 않았다. 배포 시에는 깨끗한 테스트 완료 커밋과 production 계보를 확인하고, Render `activeJobs=0`, `queuedJobs=0` 확인 후 비강제 production push를 배포 시작점으로 삼는다. live 커밋·`/healthz`·내부 엔진 버전을 확인하고, 문제 시 직전 운영 커밋으로 복귀한다.

## 후속 보강: 비교 범위·절차 순서·신청서 문구

- `relationScopeRestore`: 같은 명사구에 붙은 `보다→이/가 아니라`, `이/가 있어도→만으로` 변화를 원문의 관계 표지만 복원한다. 소유 문장 대응이 모호하거나 인용/코드·다른 원문 절의 정상 배제 표현이면 수정하지 않는다. 수정은 최초 의미 심사 앞과 마지막 재검증 앞에 적용하며 통과 판정을 대신하지 않는다.
- 문장 한 개가 2~3개로 분리된 경우까지 준비/확인과 수행의 상대 순서를 심사 후보로 올린다. 명시적인 회상과 모호한 대응은 제외한다. 대상 쌍 12개로 계산량을 제한하고, 일반 문서에는 추가 정렬을 수행하지 않는다.
- 절차·조건·비교 후보는 기존 설정의 확정 심사 모델 경로를 사용한다. 모델 설정·과금 정책·최대 수리 횟수는 변경하지 않았다.
- 명시적 신청서와 동의 체크박스가 있는 경우에만 bounded 동의문 행을 보호한다. 뒤의 수기·경험 본문은 계속 편집한다. 누락된 PDF 좌표나 구분자를 추측 복원하지 않는다.
- 신규 관측 `relationScopeRestoreCount`는 국소 복원 적용 횟수이며 의미 검증 성공 건수가 아니다.
