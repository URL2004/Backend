# v2.5.65 텍스트 처리 성능 회귀 후속 검증

2026-09-24. 비교 기준: 최적화 전 후보 `5b21b9f`(운영 기준은 `09dde773`).

## 반복 재현과 수정

1. 인용 밀집 50,000자에서 장르 판정 지연을 재현했다. 동일 인용 분석이 format·genre·line 판정에서 반복되고, 인용×span 및 인용×행 전체 검색과 수정마다 문자열 전체 복사가 겹쳤다. 순차 span/행 포인터와 단일 문자열 조립으로 바꾸고, 동일 장르 판정 호출 안에서만 분석을 재사용한다. 원문을 전역 캐시에 보관하지 않는다.
2. 문장 분리기가 구두점·개행마다 전체 인용 목록을 탐색했다. 정렬된 span과 prefix 최대 끝 위치를 이용한 이진 검색으로 치환했다. 포함 경계의 `<`/`<=`, 중첩 인용·괄호·코드 규칙은 유지한다.
3. 행 분류기가 각 행의 위치를 전체 행 배열에서 다시 찾았다. 인덱스 기반 순차 순회로 교체했다.
4. 가독성 검사에서 구조 판정·라벨 판정·분할 필요량 계산이 같은 문단과 문장을 반복 분석했다. 한 문단 안에서 계산 결과를 재사용한다. 장르 위험 분석도 이미 나눈 문장을 재사용한다.
5. 자소서에서만 소비하는 원문 레이아웃·완결 행 정보를 모든 장르에서 계산했다. 자소서에만 한 번 계산하며, 사용하지 않던 가독성 보고서 전체 생성을 제거했다.

모델·프롬프트·추론 강도·가격·과금·전달 정책·동시성·캐시 정책은 이번 성능 최적화에서 변경하지 않는다. 앞선 v2.5.65 기능 수정과 구분하여 결과 동일성을 검사했다.

## 검증

- 전체 자동 테스트 1,940개 통과, 실패·스킵 0. 성능 수정 중 반복 실행하고 마지막 코드에서도 통과했다.
- 저장 로그 986건 + 합성 1,500건, 원문/결과를 포함한 3,065개 텍스트에서 문장 span·종결 판정·인용 수정·행 분류·가독성 판정 동일. 저장 입력의 장르 판정도 동일. 원문 또는 결과 전문은 저장소에 포함하지 않았다.
- 휴머나이징 579쌍의 비동기 문단 복원을 최적화 전후 교차 순서로 전수 실행했다. 결과 문자열·pass·policy·목표 문단 수·가독성 판정 차이 0건.
- 579쌍 문단 복원 p50: 7.92 → 4.04ms, p95: 48.02 → 26.41ms. 최장 1,386.6 → 1,248.4ms. 이는 로컬 함수 실행 시간이지 모델·대기열·네트워크를 포함한 운영 처리시간이 아니다.
- 최종 합성 프로브(각 10회): 50,000자 장르 판정 p50 75.7ms, p95 98.4ms. 인용 수리 p50 4.38ms. 앞서 확인한 최적화 전 약 522ms 회귀는 해소했지만 서로 다른 실행의 수치를 정밀한 운영 개선율로 발표하지 않는다.
- 20문단·120문장 동시 3건: 묶음 p95 50.0ms, 이벤트 루프 p95 17.1ms·최대 17.9ms. 결과 순서·내용·대기 중 취소 통과.
- `npm run benchmark:text-structure`로 공개 합성 데이터만 사용하는 성능 재현을 제공한다. 모델 호출·운영 읽기/쓰기·사용자 과금 없음. 단위 테스트에 불안정한 벽시계 임계값을 넣지 않고 독립 실행으로 측정한다.

## 한계와 배포 판단

이번 최적화에서 추가 실제 모델 호출은 없다. 앞선 전체 예산 약 4,471원은 그대로다. byte/판정 동일성 검사로 로컬 최적화의 회귀를 검증했으며 신규 생성 전수검사를 수행했다고 주장하지 않는다.

매우 큰 입력의 장르 판정은 여전히 동기 계산이다. 모든 입력·모든 호스트 부하에서 이벤트 루프 지연 50ms 이하를 보장하지 않는다. 중간 비교 실행에서는 최대 98ms도 관측했으며, 실제 운영 p95·비용·오류율은 별도 관측이 필요하다. 어려운 문단 정렬도 최장 1초 이상 남는다. 확인된 신규 성능 회귀와 기능 동일성 검증은 해소했지만 전체 서비스 병목이 0이라는 뜻은 아니다.

배포에는 기존 3개 기능 수정 커밋과 이번 최적화를 함께 포함한다. 배포 직전 운영 HEAD·작업 수·predeploy를 확인하고, 완료 여부와 실제 배포 식별자는 별도 운영 기록에 남긴다.
