## 1. 결론

현재 우리 페이지는 이미 단순 랜딩이 아니라 **AI 감지/휴머나이징 작업실**에 가깝다. 따라서 추천 기준은 “화려해 보이는가”보다 아래 4개가 우선이다.

1. 사용자가 지금 무엇을 해야 하는지 더 빨리 알게 하는 컴포넌트
2. 긴 작업 중 불안감을 낮추는 진행 상태 컴포넌트
3. 결제/크레딧/검출률 같은 민감한 정보를 더 명확하게 보여주는 컴포넌트
4. Q&A/FAQ/설정처럼 정보량이 많은 영역을 접고 펼치는 컴포넌트

가장 먼저 써볼 만한 것은 다음 10개다.

| 우선 | 추천 컴포넌트 | 출처 | 적용 위치 | 이유 |
|---:|---|---|---|---|
| 1 | [AI Input](https://smoothui.dev/docs/components/ai-input) / [Animated Input](https://smoothui.dev/docs/components/animated-input) | SmoothUI, Uiverse | 메인 입력 컴포저 | 현재 입력창이 핵심 전환 지점이다. 명령 힌트, 파일 첨부, 전송 상태를 한곳에서 정리할 수 있다 |
| 2 | [Animated Stepper](https://smoothui.dev/docs/components/animated-stepper) | SmoothUI | 휴머나이징 플로우, 긴 작업 상태 | 분석 -> 목적 선택 -> 근거 승인 -> 변환 -> 완료 흐름을 명확하게 만든다 |
| 3 | [Animated File Upload](https://smoothui.dev/docs/components/animated-file-upload) | SmoothUI, Uiverse | PDF 업로드 | 지금은 작은 `+` 버튼이라 업로드 기능이 묻힌다 |
| 4 | [Animated Progress Bar](https://smoothui.dev/docs/components/animated-progress-bar) | SmoothUI, Uiverse | 분석/변환 진행률, 크레딧 차감 예측 | 장기 작업 불안과 “멈춘 것 같다”는 느낌을 줄인다 |
| 5 | [Accessible Accordion](https://component.gallery/components/accordion/) | Component Gallery, SmoothUI | FAQ, Q&A, 문단별 진단 | 정보량을 줄이되 접근성 기준을 지킬 수 있다 |
| 6 | [Number Ticker](https://magicui.design/docs/components/number-ticker) / [Number Flow](https://smoothui.dev/docs/components/number-flow) | Magic UI, SmoothUI | 검출률, 크레딧, 가격, 통계 | 수치 변화가 서비스 핵심 가치라 반응성을 높인다 |
| 7 | [Circular Progress](https://magicui.design/docs/components/animated-circular-progress-bar) / Gauge | Magic UI | AI 작성 확률 보고서 | 현재 반원 게이지가 있어 가장 자연스럽게 고도화 가능하다 |
| 8 | [Before/After Comparison](https://magicui.design/docs/components/code-comparison) | Magic UI Code Comparison 변형 | 변환 예시, 결과 화면 | 사용자가 돈을 내는 이유를 가장 직접적으로 보여준다 |

반대로 Magic UI의 Globe, Particles, Meteors, Warp Background, Smooth Cursor, Comic Text 같은 장식성 강한 컴포넌트는 지금 제품과 맞지 않는다. 우리 서비스는 학생이 과제/자소서/논문을 처리하는 도구라, 과장된 장식은 신뢰를 깎을 가능성이 더 크다.

## 2. 현재 페이지 관찰

### 2.1 메인 화면

현재 `main.html`의 실제 주 화면은 라벤더 셸이다.

- 좌측 사이드바: 새 문장, AI 감지 & 휴머나이저, 공지사항, 커뮤니티, Q&A, 충전하기, Pro, 보관함, 히스토리
- 상단바: 크레딧, 업그레이드, 사용 가이드, 알림, 디자인 예시
- 메인 입력: 로고, 설명문, `textarea`, 파일 업로드, 글자수, 모드 토글, 전송 버튼
- 예시 카드: AI 탐지율 전후 비교, 예시 문장 클릭 체험
- 플로우: 분석 중, 무료 감지 보고서, 목적 선택, 회피 설정, 작업 상태, 결과

이미 UI 밀도가 높기 때문에 새 컴포넌트는 “섹션 추가”보다 “기존 컴포넌트 대체/정리”가 맞다.

### 2.2 가격 페이지

`pricing.html`은 크레딧과 정기구독 탭, 쿠폰 입력, 플랜 카드, 추천 패널이 있다. 여기서는 카드 장식보다 **가격/크레딧 계산 이해도**가 중요하다.

### 2.3 커뮤니티/Q&A

커뮤니티와 Q&A는 검색, 필터, 정렬, 목록, 상세, 작성 폼, 사이드 정보 영역을 갖고 있다. 여기는 애니메이션보다 **스켈레톤 로딩, 접근성 좋은 아코디언, 검색/필터 인터랙션**이 효과적이다.

## 3. 출처별 도입 방향

## 3.1 Magic UI

Magic UI는 React/shadcn 기반 컴포넌트가 많다. 현재 프론트는 빌드 없는 정적 HTML/CSS/JS 구조이므로 바로 설치하기보다는 디자인과 인터랙션을 참고해 CSS/Vanilla JS로 흡수하는 방식이 현실적이다.

### 추천

| 컴포넌트 | 적용 위치 | 우선순위 | 적용 방식 |
|---|---|---:|---|
| Dia Text Reveal | 첫 화면 핵심 문장, 결과 완료 문구 | P1 | 한 줄 문구에만 사용. 반복 사용 금지 |
| Number Ticker | AI 탐지율, 평균 회피율, 크레딧 수치 | P0 | 숫자만 카운트업. `prefers-reduced-motion` 대응 |
| Animated Circular Progress Bar | 무료 감지 보고서 게이지 | P0 | 기존 `lav-rep-gauge`를 대체 또는 보강 |
| Code Comparison | Before/After 변환 예시 | P1 | 코드 대신 문장 비교 컴포넌트로 변형 |
| Border Beam | 주 CTA 또는 선택된 플랜 | P1 | 한 화면에 1개만. 카드 전체 남발 금지 |
| Shine/Shimmer Button | 전송/결제 CTA | P2 | 기본 버튼 상태가 먼저 안정된 뒤 제한 도입 |
| Text Highlighter | 결과에서 위험 문장 표시 | P1 | AI스러운 문장, 추상 표현 강조에 적합 |
| Animated List | 작업 단계 로그, 승인 근거 목록 | P1 | 새 항목 등장만 부드럽게 |
| Scroll Progress | 긴 결과/보고서 읽기 진행률 | P2 | 결과 화면이나 긴 Q&A 상세에서만 고려 |
| Progressive Blur | 긴 목록 하단 페이드 | P2 | 커뮤니티/Q&A 목록 끝 처리에 제한 사용 |

### 제한 추천

| 컴포넌트 | 판단 |
|---|---|
| Bento Grid | 랜딩 아래 기능 소개에는 가능. 현재 메인 작업실 상단에는 불필요 |

## 3.2 Uiverse

Uiverse는 CSS/Tailwind 단품이 많고, 사이트 기준 전체 요소와 Buttons, Inputs, Loaders, Cards, Toggle switches, Tooltips, Forms 등 카테고리가 있다. 현재 저장소 구조에는 Uiverse 방식이 가장 쉽게 맞는다. 또한 Uiverse 페이지는 UI 요소가 MIT License로 제공된다고 안내한다.

### 추천

| 카테고리 | 적용 위치 | 우선순위 | 적용 방식 |
|---|---|---:|---|
| Inputs | 메인 입력창, 쿠폰 입력, Q&A 검색 | P0 | 포커스 링, 글자수 경고, 유효성 상태만 차용 |
| Buttons | 전송, 결제, 복사, 다운로드 | P0 | 과한 3D 제외. 기본/위험/성공 상태 체계화 |
| Loaders | 분석 중, 결제 처리, 목록 로딩 | P0 | 현재 스피너를 통일된 로더/스켈레톤으로 정리 |
| Toggle switches | 근거 보강, 익명 작성, 모드 선택 | P0 | 접근성 라벨과 disabled 상태를 명확히 |
| Radio buttons | 기본 피하기/고급 피하기, 분량 선택 | P0 | 현재 카드형 라디오의 선택감을 강화 |
| Tooltips | 아이콘 버튼, 크레딧 계산, 무료 배지 | P1 | 작은 설명만. 사용법을 장황하게 넣지 않음 |
| Cards | 가격 플랜, Q&A 사이드 정보 | P1 | 현재 카드 반경/그림자 체계에 맞춰 부분 차용 |
| Forms | 커뮤니티/Q&A 작성 폼 | P1 | validation, error text, submit disabled 상태 보강 |

## 3.3 Component Gallery Accordion

이 출처는 단일 컴포넌트 코드보다 **접근성 기준** 참고 가치가 크다. Accordion은 FAQ, Q&A, 문단별 진단, 가격 안내처럼 정보가 많은 곳에 바로 적용 가능하다.

### 추천 적용

| 위치 | 현재 상태 | 추천 |
|---|---|---|
| 메인 하단 FAQ | `button onclick="toggleFaq(this)"` 구조 | `aria-expanded`, `aria-controls`를 명시한 접근성 아코디언으로 교체 |
| 무료 감지 보고서 문단별 진단 | 여러 문단을 전부 노출 | 첫 1~2개만 열고 나머지는 접기 |
| 근거 승인 후보 | 후보가 많으면 길어짐 | 출처별 accordion 또는 details로 묶기 |
| 가격 안내 | “어떤 플랜이 맞을까요” 카드가 많음 | 모바일에서는 accordion으로 변환 |
| Q&A 상세 | 답변/추가 정보가 길 수 있음 | 질문, 답변, 처리 상태, 결제 정보 분리 |

### 구현 기준

- 제목은 실제 버튼이어야 한다.
- 버튼에 `aria-expanded`를 둔다.
- 버튼과 콘텐츠를 `aria-controls` + `id`로 연결한다.
- 아이콘은 보조기기에 읽히지 않도록 `aria-hidden="true"` 처리한다.
- 모바일에서는 유리하지만, 필수 정보는 아코디언 안에 숨기지 않는다.
- 한 번에 하나만 열리게 강제하지 않는다. 사용자가 여러 항목을 비교할 수 있어야 한다.

- 현재 사이드바는 이미 기능이 많다. 새 애니메이션보다 hover/focus/active 상태 통일이 먼저다.
- 모바일 메뉴는 drawer 패턴으로 정리할 가치가 있다.
- 알림 dot은 실제 알림 수와 연결되기 전까지 과장하지 않는다.

## 8. 바로 만들 컴포넌트 후보 스펙

## 8.1 `gp-toast`

- 용도: 복사 완료, 쿠폰 적용, 결제 실패, 크레딧 부족, 작업 복구
- 형태: 우하단 또는 모바일 하단
- 상태: success, warning, error, info
- 지속 시간: 3~5초
- 필수: `aria-live="polite"` 또는 error는 `assertive`

## 8.2 `gp-accessible-accordion`

- 용도: FAQ, 문단별 진단, 근거 후보, 가격 안내
- 구조: `button[aria-expanded][aria-controls] + div[id]`
- 옵션: multiple open 허용
- 모바일: 기본 collapsed
- 주의: 결제/보장/개인정보 고지 같은 필수 정보는 숨기지 않음

## 8.3 `gp-stepper`

- 용도: 분석/설정/근거/변환/완료
- 형태: desktop horizontal, mobile vertical
- 상태: idle, active, done, error
- 연결: `lav-flow-card`의 `data-flow`와 동기화
- reduced motion: slide 대신 opacity만

## 8.4 `gp-upload-chip/dropzone`

- 용도: PDF 업로드
- 기본: 작은 chip
- drag-over 또는 클릭 후: 확장 dropzone
- 표시: 파일명, 크기, 제거, 에러
- 제한: PDF 중심. 지원하지 않는 형식은 즉시 안내

## 8.5 `gp-number-ticker`

- 용도: AI 확률, 크레딧, 가격, 통계
- 옵션: start, end, duration, decimals
- reduced motion: 즉시 최종값 표시
- 주의: 금액과 크레딧은 실제 값과 불일치하면 안 됨

## 9. 최종 추천 순서

가장 실용적인 순서는 다음이다.

1. Toast 시스템
2. FAQ/진단 Accordion 접근성 개선
3. Stepper 진행 상태 개선
4. PDF 업로드 UI 개선
5. Number Ticker + Circular Gauge 보강
6. Before/After comparison 개선
7. 가격 페이지 수치/쿠폰 피드백 개선
8. Tooltip/Badge 체계 정리
9. Q&A/커뮤니티 skeleton loading
10. Dia Text Reveal 같은 감성 요소는 마지막에 1~2곳만

이 순서가 좋은 이유는 명확하다. 현재 제품에서 사용자가 실제로 막히는 지점은 장식 부족이 아니라 **입력, 진행 상태, 결과 신뢰, 결제/크레딧 이해, 문의 탐색**이다. 위 컴포넌트들은 그 지점을 직접 개선한다.

## 10. 요약

외부 사이트에서 가져올 만한 후보는 많지만, 우리 페이지에 맞는 것은 크게 5종류다.

1. 입력/업로드: AI Input, Animated Input, File Upload
2. 진행 상태: Stepper, Progress Bar, Loader, Skeleton
3. 결과 설득: Number Ticker, Circular Gauge, Before/After Comparison, Text Highlighter
4. 정보 정리: Accordion, Tooltip, Popover, Drawer
5. 결제/운영 피드백: Toast, Notification Badge, Price Flow

우선순위는 “예쁜 효과”가 아니라 “고객지원 문의를 줄이고, 무료 감지에서 유료 변환까지의 길을 더 명확하게 만드는 것”이다.
