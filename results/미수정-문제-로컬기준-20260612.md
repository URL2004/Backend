## 1. 미수정 — 우선 처리 필요

### P0-1. 중복 차감 방지(멱등성) 부재 ★★★

- **민원**: 한 번 입력했는데 2~4번 차감, "55크레딧씩 3번"(#11, #16, #21). 오류 후 재시도하니 크레딧만 누적 소멸.
- **현재 코드**:
  - 차감 자체는 안전하게 재설계됨 — 클라이언트 직접 차감 제거(`app-module.js:771-774`), 백엔드 `runTransaction` 후차감(`analyze.js:38-55 commitCreditDeduct`), 끊김/타임아웃 시 차감 스킵·자동 복구(`commitCreditRestore` `analyze.js:59-75`).
  - **그러나 차감에 멱등키가 없다.** `creditHistory` 문서는 매 호출 새 auto-ID(`analyze.js:49 .doc()`). 동일 작업이 서버에 2번 도달하면 2번 차감. 요청 단위 requestId/nonce/lock 부재(`/analyze`에 0건). 멱등성은 구독 결제에만 존재(`subscription.js:231-233`).
  - 프론트는 5xx·네트워크 오류·청크에서 재시도(`app-main.js:729,736,740`, 청크 `maxRetries:3`). **"서버가 차감+응답까지 끝냈으나 응답 패킷만 유실 → 프론트 네트워크오류로 인지 → 재시도 → 중복 차감"** 경로가 남음. 이 경우 `req.on('close')` 복구는 트리거 안 됨.
- **판정**: **미수정**. 정상 disconnect는 복구되지만 "성공+응답유실 후 재시도"는 못 막는다. 복구 재시도가 소진되면 "수동 보정 필요" 로그만 남김(`analyze.js:2906-2908`, `transform.js:227`).
- **권장**: 작업당 `requestId`(UUID)를 프론트가 생성, 재시도 시 동일값 전송 → 서버는 `creditHistory` 문서 ID를 `requestId`로 고정(`.doc(requestId)`)하고 트랜잭션 내 존재 시 차감 skip. 청크는 `requestId:chunkIndex`로 키.

### P0-2. 기본 "다듬기"가 외부 검출 회피를 못 함 (이중구조) ★★★

- **민원**: 휴머나이징 후에도 카피킬러/GPT킬러/제로GPT에서 AI율 100/95/88/83/70% 유지(#33,34,35,36,43,45,48,68,70,71,76,79,80,92,97,106,111,113,119,154,155,157 등 — 단일 최다 유형).
- **현재 코드**:
  - 외부검출 회피 풀스택(burstiness·grounding·antiDetect·FLOOR 게이트)은 **`engine:'floorV2'`를 보낸 호출에서만** 실행(`analyze.js:2734`, `runHumanizeChunked`).
  - 기본 "그대로 다듬기"와 `app-main.js`의 직접 호출은 `engine` 필드 없이 → 레거시 분기(`analyze.js:2767`)로 가서 표면지표(콤마·hedge·종결어미)만 다듬고 회피 재생성을 안 함.
  - 코드 주석이 이를 자인: 보존형 다듬기 C등급 87~100% vs 블로그 회피 27~54%(`diagnose.js:14-19`).
- **판정**: **부분수정**. 회피 엔진은 실연결됐으나 "블로그/재구성"을 안 고르면 검출률이 거의 안 떨어지는 레거시로 감.
- **권장**: ① 기본 다듬기에도 floorV2 적용 검토, 또는 ② UI에서 "그대로 다듬기는 외부 검출 회피가 약함"을 명시해 기대치 관리(보존형 다듬기는 구조상 검출률을 못 낮춘다는 기존 실측과 일치). 광고 문구("AI 안 걸린다")와 기본 경로 성능 격차가 환불 민원의 근본 원인이므로 **광고-실제 정합성**이 핵심.

### P0-3. 레거시 긴글: 청크별 사전차감 → 마지막 청크 잔액부족 중단 ★★★

- **민원**: 16190자에 "55크레딧씩 3번 빼가고 99%에서 크레딧 부족으로 중단"(#120), 5500자/2만자 길이초과 안내·분할 중 소멸(#9,11,12,79).
- **현재 코드**:
  - 레거시: 프론트가 5500자 초과 시 4500~5500자 청크로 순차분할(`app-main.js:649,929 runChunkedText`), **청크마다 별도 `/analyze` 호출·별도 차감**(`ceil(len/100)`, `app-main.js:801`). 앞 청크들이 차감을 다 가져가 **마지막 청크에서 잔액부족이면 중단** → 부분 결과만 받고 크레딧 소진. 전체 필요크레딧 선검증(precheck total)이 없음.
  - 회피/재구성 경로는 양호: 서버청킹(`chunk.js`)+병렬+청크 재시도+완료시점 차감(`transform.js:287,221`, `analyze.js:2262`).
- **판정**: **부분수정**. 신규 경로는 잘 됐지만 **레거시 청크 경로의 사전차감 구조가 민원 직접원인 그대로** 남음.
- **권장**: 레거시 청크도 시작 전 전체 필요크레딧 일괄 precheck(부족하면 시작 자체를 막음), 또는 완료시점 일괄차감으로 전환.

### P1-1. 영어 → 한국어 오변환 ★★

- **민원**: 영어 글을 영어로 변환했는데 결과가 한국어로 출력(#124, #145 — #145는 조회수 62로 최상위권).
- **현재 코드**: `lang` 파라미터·영어 프롬프트 분기(`isEn`)는 존재하나,
  - ① 프론트 `selectedLang` 기본값 `'ko'`, 사용자가 언어 토글을 눌러야만 바뀜(불일치 시 경고만, `app-main.js:166-167`).
  - ② **회피 블로그 경로 `runBlogEvasion`이 `callEvasionApi` 호출 시 `lang`을 아예 안 넘김** → `callEvasionApi`에서 `lang: payload.lang || 'ko'`로 **항상 한국어 강제**(`evasion-flow.js:389,470`). 서버측 언어 자동감지 없음.
- **판정**: **미수정**(회피 경로). 영어 입력이라도 무조건 ko 처리.
- **권장**: `runBlogEvasion`/`callEvasionApi`에 `selectedLang` 전달 + 입력 한글비율(`koRatio`는 이미 `app-main.js:163`에서 계산 중) 기반 `lang` 자동결정.

### P1-2. 문체(평서체/경어체) 선택 미구현 — 개발자 약속분 ★★

- **민원**: 대학과제에서 "~다/-이다" 평서체 원하는데 "~습니다"로 강제(#7,#86). 개발자가 #86에서 "문체 선택 옵션을 앞으로 제공하겠다"고 명시 약속.
- **현재 코드**:
  - 레거시 과제/이력 프롬프트는 **경어체 강제·평어 금지 명문화**(`prompts.js:156, 398`).
  - floorV2는 원문 register 자동감지로 평어/존대 유지(`contract.js detectRegister`)하나 **사용자 선택 파라미터가 아님**. `ASSIGNMENT_B7=1` env면 오히려 경어 강제.
  - 요청 바디·UI 어디에도 `register`(문체) 선택 인자/토글 없음. 프론트의 `lavTone`은 블로그↔격식(장르 레지스터)이지 평서↔경어가 아님(`main.html:238-256`).
- **판정**: **미수정(미구현)**. 약속한 문체 선택 옵션 미이행.
- **권장**: 요청 바디에 `register: 'plain'|'polite'` 추가 → 프롬프트 [문체 통일] 블록에 배선(블록은 이미 register를 받음). UI에 평서체/경어체 토글 노출.

### P1-3. 카카오 회원탈퇴: 비밀번호 추측 재인증 결함 ★★

- **민원**: "탈퇴하려고 하면 실패 뜸" 반복(#40,#61,#62,#91). 운영자는 "고객센터 메일로"로 우회.
- **현재 코드**: 탈퇴가 백엔드 라우트 없이 프론트 Firebase Client SDK로 처리(`app-module.js:675 deleteAccount`).
  - Firebase `deleteUser`가 최근 로그인 요구 → 재인증 강제(`app-module.js:699-717`).
  - **카카오는 하드코딩된 비밀번호 2패턴 추측**: `'kakao_'+kakaoId+('_!@#'|'_pw!')`을 시도, 둘 다 실패 시 `throw '카카오 계정 재인증에 실패했습니다.'`(`:704-716`). 패턴 불일치 카카오 계정은 **구조적으로 탈퇴 불가**.
  - Google은 `reauthenticateWithPopup`(`:701`) — 모바일/인앱브라우저 팝업 차단 시 실패 가능.
- **판정**: **미수정(부분 결함)**. 기능은 있으나 카카오 유저 다수가 항상 실패할 수 있는 구조.
- **권장**: 비밀번호 추측 제거 → 백엔드에 Admin SDK `auth().deleteUser(uid)` 탈퇴 라우트 신설(idToken 검증 후 서버 권한 삭제). 팝업 차단 대비 redirect 재인증 폴백.

## 2. 부분수정 — 레거시 잔존 / 마무리 필요

### P2-1. 레거시 "내용 임의추가" soft-refine (하드블록 없음) ★

- **민원**: 원문에 없는 참고문헌·내용 추가, 1000자를 몇 배 증축, 결론이 항상 같은 다짐 문구(#86,#100,#118). 개발자 "추가 금지 조치 완료"(~5/23) 답변.
- **현재 코드**: 프롬프트 가드(없는 사실 주입 금지, 분량 ×0.9~1.1)·서버 lengthRatio 검출 존재. 회피/재구성 경로는 novelty·lostFacts·length를 **critical 하드게이트로 차단**(`floor.js:411-431` → 422). **그러나 레거시 다듬기는 novelty를 측정·2-pass refine만 하고 실패해도 결과를 반환(하드블록 없음)** → 잔존 novelty가 출력될 수 있음.
- **판정**: **부분수정(경로별 상이)**.
- **권장**: 레거시도 novelty refine 실패 시 하드 차단(또는 floorV2 통합), lengthRatio 상한(>1.2) 하드게이트 추가.

### P2-2. 네비 라벨 "분석/AI 감지" 우선 인상 ★

- **민원**: "분석만 되고 휴머나이징 버튼이 안 보임"(#3,14,31,46,47,49,50,96,102,110,144,151,153,156 등). 운영자가 매번 "AI 감지 탭을 눌러야 모드 나옴"이라 안내(숨은 진입).
- **현재 코드**: 라벤더 UI에서 입력창 바로 아래 "휴머나이징/AI 감지" 세그먼트가 **기본 노출·휴머나이징 기본 활성**(`main.html:114-117`), 모바일에서도 안 숨음(`redesign.css:11126`) → **발견성 자체는 수정됨**. 단, 사이드바 메인 라벨 "AI 감지 & 휴머나이저"(`main.html:51`), 모바일 하단탭 "분석"(`mobile-nav.html:14`)로 진입 라벨에 감지 우선 인상이 남음.
- **판정**: **부분수정**(핵심 발견성 해소, 라벨 잔여).
- **권장**: 모바일 하단탭 "분석"→"휴머나이저/변환", 사이드바도 휴머나이저 우선 순서.

### P2-3. 회피 스테퍼 다단계 마찰 ★

- **현재 코드**: 휴머나이징을 눌러도 진단→방법선택→(AI 티 줄이기 시)어투/분량/근거/메모 설정→확인 모달까지 3~4스텝(`main.html:201-285`). "빠른 변환" 사용자에겐 단계 증가. ("그대로 다듬기"는 한 번에 직행하는 빠른 경로 존재.) 격식 재구성은 200~600크레딧·40~90분(`evasion-flow.js:300-308`)으로 무거움.
- **판정**: **부분수정**(발견성·가치전달↑, 변환까지 단계↑).
