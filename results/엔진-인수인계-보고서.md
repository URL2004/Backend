# 당근대학생 AI 휴머나이저 엔진 — 인수인계 보고서

> 대상: 외주 개발자 / 작성 기준: `rebuild/floor-v2-backend` 브랜치 (main 대비 +126 커밋, 109파일 변경, +16,672줄)
> 한 줄 요약: **"카피킬러(AI 탐지) 우회를 하되, 사실·화자·결론을 절대 왜곡하지 않는다(FLOOR)"** 를 보장하는 한국어 글 휴머나이저 백엔드.

---

## 0. 제품이 하는 일

학생이 쓴(또는 AI가 쓴) 한국어 글을 입력받아 → **사람이 쓴 것처럼 자연스럽게 다듬어** → 카피킬러 AI생성검사 % 를 낮춘다.
단, **없는 사실·경험을 지어내지 않고** 원문의 사실·수치·고유명사·화자·결론을 그대로 유지한다(이게 핵심 차별점이자 안전장치).

- 스택: Node.js + Express, Anthropic Claude API (Sonnet 4.6 / Haiku 4.5)
- 진입점: `server.js` → `routes/analyze.js`
- 의존성: express, cors, multer, pdf-parse, firebase-admin, express-rate-limit, dotenv

## 1. main(구버전) 대비 무엇이 달라졌나

| | **main (구버전)** | **현재 (floor-v2 재구축)** |
|---|---|---|
| 구조 | `prompts.js` 단일 프롬프트 + `analyze.js`(2247줄) | `engine/` 16개 모듈 + `analyze.js`(2899줄) + `eval/` 검증 하네스 |
| 휴머나이즈 | **글 전체를 한 번에** 프롬프트로 재작성 | **문단 단위 청킹 → 청크별 재작성 → 병합** |
| 품질 보증 | 없음 (프롬프트에 "지어내지 마라"만 명시) | **FLOOR 시스템**(결정론 측정 + LLM 판정)으로 날조·왜곡을 *코드로* 차단 |
| 입력 분류 | 없음 (모든 글 동일 처리) | **A/B/C 등급** 자동 분류 → 등급별 다른 처리 경로 |
| 우회 강화 | 프롬프트 의존 | 측정 기반 **후처리 패스 스택**(연결어 예산·문장 버스티니스·중복 제거) |
| 비용 | 전부 Sonnet | **모델 티어링**(생성=Sonnet, 단순편집=Haiku) |
| 검증 | 없음 | `eval/` 자동 회귀 테스트(88케이스) + 카피킬러 실측 캘리브레이션 |
| 모드 | 사실상 1종 | **4종**(assignment/blog/thesis/resume) — 홈페이지 4개 선택지와 매칭 |

→ **사실상 엔진을 새로 만든 수준(near-total rewrite).** main에는 `engine/` 디렉터리 자체가 없었음.

## 2. 엔진 동작 방식 (전체 파이프라인)

입력 글 1개가 출고되기까지의 순서 (`routes/analyze.js`의 `runHumanizeChunked`):

```
[입력 글]
   │
   ▼
① 청킹 (engine/chunk.js)
   문단 단위로 N개 청크 분할 (보통 1문단=1청크)
   │
   ▼
② 입력 등급 분류 (engine/surfaceguard.js · classifyInputRisk)
   abstractRiskRatio(구체 근거 없는 문단 비율) 계산 → A / B / C 등급
   │
   ▼
③ 청크별 휴머나이즈 (engine/prompt.js + analyze.js, 모델=Sonnet)
   각 청크를 모드별 톤으로 자연스럽게 재작성
   동시에 청크별 FLOOR 검사(judge)
   → 병합 = baseline
   │
   ▼
④ 등급별 강화 패스
   • A/B 등급: grounding → optimize → polish 실행 (구체·견해 있어 도움)
   • C 등급(순수 추상): 위 3개 SKIP (추상글엔 오히려 악화) — skipPasses
   │
   ▼
⑤ 무해 패스 (등급 무관, 내용 불변)
   • phrasebudget : "거든요/근데/결국…" 과다 반복 연결어 정리 (C등급 단독실행)
   • burstiness   : 문장 길이 들쭉날쭉하게 (기계적 균일성 깸)
   │
   ▼
⑥ acceptance gate
   ④⑤ 스택이 baseline보다 {중복·반복·분량팽창} 나빠지면 baseline으로 롤백
   │
   ▼
⑦ dedup (engine/dedupe.js)
   휴머나이저가 도입부 등 중복 생성한 문장 제거 (게이트 이후 = baseline 중복도 제거)
   │
   ▼
⑧ (옵션) antiDetect → spacing(띄어쓰기 교정)
   │
   ▼
⑨ 출고 판정 (engine/floor.js · collectFloorViolations)
   FLOOR 위반 있으면 BLOCKED, 없으면 CLEAN
   │
   ▼
[출력 글]
```

핵심 설계 철학: **"생성은 강하게(Sonnet), 측정·판정은 결정론 우선, 편집은 싸게(Haiku), 안전(FLOOR)은 절대 양보 안 함."**

## 4. 핵심 개념 4가지 (개발자가 꼭 알아야 할 것)

### (1) FLOOR — 절대 우선 안전장치
"우회(% 낮추기)"보다 **항상 우선**한다. 두 층으로 구성:
- **결정론 측정**(floor.js/surfaceguard.js): measureNovelty(새 사실), measurePersonalExperienceNovelty(1인칭 일화 날조), measureLostFacts(사실 증발), measureRepetition(반복), measureLength(분량)
- **LLM 판정**(judge.js): 원문에서 "허용된 유일 주장 원장(ledger)"을 뽑고, 출력이 원장 밖 주장을 했는지 semanticJudge로 검사
- 위반 시 출고 **BLOCKED**. 어떤 우회 패스도 FLOOR를 못 넘는다(패스 결과가 위반을 늘리면 그 패스 롤백).

### (2) 입력 등급 A/B/C
`abstractRiskRatio` = 구체 근거(실제 장면/숫자/고유명사)가 없는 문단 비율.
- **A** (<0.35): 구체 풍부 → 휴머나이즈+패스 풀가동
- **B** (0.35~0.80): 혼합 → 풀가동
- **C** (≥0.80): 순수 추상 일반론 → grounding/optimize/polish **SKIP**(추상글엔 악화), 무해 패스만
- 이유: 실측상 추상글에 stance/구체를 *추가*하면 더 AI 같아짐(공부글 57→73 악화 사례).

### (3) 후처리 스택 (이번 세션 핵심 성과)
구조적 AI 신호("기계적 정확성·균일성")를 결정론으로 제거:
- **phrasebudget**: 같은 연결어 과다(예: "거든요" 58회) → 다양화. 단독 효과 risk 0.63→0.52
- **burstiness**: 문장 길이 균일 → 들쭉날쭉. 단독 효과 risk 0.63→0.54
- 두 개가 **다른 신호라 복리로** 작동: 스택 시 risk 0.63→0.45
- → 순수 추상 도시론 실측 **87% → 32%** (무날조)

### (4) 비용 모델 티어링
- **생성(품질 좌우)** = Sonnet 4.6: humanize, grounding/optimize stance 생성
- **판정의 뇌** = Sonnet 4.6: ledger 추출, semanticJudge (불완전하면 거짓 BLOCK → 반드시 Sonnet)
- **단순 편집(다수 호출)** = Haiku 4.5: repair, polish, phrasebudget, 웹검색
- C등급은 강화 패스 SKIP으로 호출 ~60개 절감(긴 추상글에서 167→73 호출)

- register-lock(원문 문체 유지)은 현재 assignment/thesis만 → **resume에도 추가 필요**(자소서가 한다체로 드리프트하는 문제).

## 6. 이번 세션에서 잡은 잠복 버그 3종 (다양한 글 테스트로 발견)

1. **Haiku 티어링 부작용** — ledger를 Haiku로 만들면 원문 주장 누락 → 충실한 패러프레이즈를 "신규 주장"으로 거짓 BLOCK. → **ledger+semanticJudge를 Sonnet으로 복원**(문서당 1~2회라 비용 무시).
2. **휴머나이저 도입부 중복 생성** → repetition BLOCK. → **dedupeSentences 추가**(floor와 동일 척도, 후속 등장만 삭제=무손실).
3. **all-or-nothing FLOOR 게이트 전체거부** — 구체 많은 글에서 Haiku가 1인칭 일화 첨가(experience_novelty) → 문단 1개가 21개 좋은 수리를 통째로 거부. → **세 재작성 패스(phrasebudget/burstiness/polish) per-segment 가드에 experience_novelty 추가**(나쁜 문단만 내부 탈락).

→ 모두 다양한 유형의 글(추상 시사·구체 산업·1인칭 자소서)을 돌려서 드러난 변동성 버그. 전부 수정·커밋, eval 88/88 유지.

## 7. 성능 (카피킬러 실측, 전부 무날조)

순수 추상 C등급(blog 모드 측정):
| 글 | 원문 | 출고 | 비고 |
|---|---|---|---|
| 도시 | 87% | **32%** | 길고 중간플래그 1 |
| 전기차 | ~85% | **34%** | 짧지만 구체 다수 |
| 숏폼 | ~85% | **36%** | 최단(15영역) |
| 저출산 | 88% | **40%** | 중간플래그 5 |
| 우주 | ~85% | **50%** | 짧고 격식 논증체 |

모드별 차이 (같은 글, 모드만 변경):
| 글 | blog | 올바른 모드 | 해석 |
|---|---|---|---|
| 자소서 | 57% | **35%** (resume) | resume에서 grounding 적용 → 하락 |
| 전기차 | 34% | **81%** (assignment) | 격식 비인칭체 → **급등** |

**★ 핵심 발견 — 카피킬러는 "비인칭·객관·격식 학술체"를 강하게 잡고, "1인칭·주관·구어체"를 봐준다.**
- blog의 "거든요·잖아요·~죠·솔직히" = 단순 톤이 아니라 **주관성/1인칭 목소리 주입** → "주관성 배제·비인칭·추상" 플래그 회피
- assignment의 "~다·~이다·~된다" 격식체 = 본질적으로 비인칭·객관 → 그 플래그 직격 (81% PDF: 중간 10개 대부분이 "추상적·구체근거부족·주관성의 지나친 배제", 기계적균일성은 단 1개)
- → **격식 모드(assignment/thesis)는 우회에 구조적으로 불리.** 미해결 과제: 격식 모드는 C등급이어도 grounding을 실행해 학술적 1인칭 견해/판단("~라고 본다", "이는 ~를 시사한다")을 주입해야 주관성배제 플래그가 꺼짐 (현재는 C등급에서 grounding skip — blog 기준 규칙이라 격식 모드엔 부적합).

법칙: **출고% ≈ f(주관성/1인칭 목소리 유무, 중간(내용)플래그 수, 길이).** 구조 스택은 "낮음(균일성)"을 제거하고, 바닥은 "중간(추상·구체근거부족·주관성배제)"이 결정 → 그 아래로 내리려면 구체 주입(evidence-pack) + 격식 모드는 주관성 주입(grounding) 필요.

## 8. 알려진 한계 / 다음 작업

- **보고서형(헤더·목차·참고문헌)** 미지원: 마크다운 헤더(## )가 산문화되며 파괴됨. "헤더 보존(humanize 건너뛰기)" 기능 필요.
- **resume register-lock 부재**: 자소서가 한다체로 드리프트(말투 혼합). assignment/thesis처럼 register-lock 추가 필요.
- **evidence-pack(미구현)**: 추상글 중간(내용)플래그를 없애는 유일한 검증된 레버. 사용자가 구체(사례·수치·경험) 메모 제공 → 일반론 문장을 구체로 교체. C등급 20%대 가능.
- **점수기(riskScore) 한계**: baseline에선 카피킬러와 상관 높으나(0.6≈0.61), 개입 후엔 괴리 → 개입 후엔 실측만 신뢰.
- **모드 재측정**: 8편을 전부 blog로 측정했으나 올바른 모드(시사=assignment, 자소서=resume)면 더 낮을 수 있음.
