## 1. Vercel Frontend env

Production 배포 전에 Vercel 프로젝트에 아래 env를 설정한다.

```env
VITE_APP_ENV=production
VITE_SITE_URL=https://gpkorea.ai.kr
VITE_API_BASE=https://ai-backend-3xtk.onrender.com
VITE_KAKAO_JS_KEY=ad2364a2d83abfe7ad22e6cdd3162dfd
VITE_KAKAO_INQUIRY_URL=https://open.kakao.com/o/s3Jegizi
VITE_MAINTENANCE_MODE=true
VITE_MAINTENANCE_PREVIEW_KEY=<프론트_점검우회키>
VITE_MAINTENANCE_MESSAGE=더 안정적인 결제와 변환 환경을 적용하고 있어요. 점검이 끝나면 바로 다시 이용할 수 있습니다.
```

일반 사용자는 점검 화면만 본다.

테스트 브라우저에서만 앱 진입:

```text
https://gpkorea.ai.kr/?preview_key=<프론트_점검우회키>
```

한 번 진입하면 브라우저 localStorage에 저장된다. 해제:

```js
localStorage.removeItem('gp_maintenance_preview_key')
```

## 2. Render Backend env

Render 운영 백엔드에 아래 env를 설정한다.

```env
MAINTENANCE_MODE=true
MAINTENANCE_BYPASS_SECRET=<백엔드_긴_랜덤_시크릿>
```

점검 중 일반 사용자 요청은 아래 쓰기/비용성 API에서 `503 maintenance_mode`가 나야 한다.

- `/analyze`
- `/analyze-pdf`
- `/diagnose`
- `/detect-report`
- `/transform*`
- `/confirm-payment`
- `/subscription*`
- `/request-refund`
- `/approve-refund`
- `/reject-refund`
- `/redeem-coupon`
- `/apply-referral`
- `/delete-account`
- `/toss/webhook`
- `/admin/*`

허용:

- `/healthz`
- `/api/health`
- `/kakao-login`
- `GET /subscription/status`
- `OPTIONS`

테스트 브라우저에서 백엔드 우회 헤더 자동 부착:

```js
localStorage.setItem('gp_maintenance_bypass', '<백엔드_긴_랜덤_시크릿>')
```

해제:

```js
localStorage.removeItem('gp_maintenance_bypass')
```

## 4. 배포 순서

1. Backend `release/prod-maintenance-test`를 Render에 배포한다.
2. `GET /healthz`에서 `maintenance: true` 확인.
3. 우회 헤더 없이 `/analyze` POST가 `503 maintenance_mode`인지 확인.
4. 우회 헤더 포함 `/analyze`가 기존 인증/크레딧 단계까지 정상 진입하는지 확인.
5. Frontend `release/prod-maintenance-test`를 Vercel Production에 배포한다.
6. `https://gpkorea.ai.kr`에서 일반 사용자 점검 화면 확인.
7. `?preview_key=...`로 앱 진입 확인.
8. 테스트 브라우저 localStorage에 `gp_maintenance_bypass`를 넣고 실환경 smoke test 진행.

## 6. 롤백

문제 발생 시:

1. `VITE_MAINTENANCE_MODE=true`는 유지해서 일반 사용자 진입을 계속 막는다.
2. Frontend는 기존 배포 또는 기존 DNS/alias로 복구한다.
3. Backend는 Render 이전 deploy로 rollback한다.
4. `/healthz`, `/analyze` 차단 여부를 재확인한다.
5. 원인 분석 후 다시 release 브랜치에서 수정한다.

## 7. 정식 오픈

테스트 통과 후:

```env
VITE_MAINTENANCE_MODE=false
MAINTENANCE_MODE=false
```

그 다음 확인:

- 일반 사용자 메인 앱 노출
- 쓰기 API 정상화
- cron 재개
- 로그에서 아래 이벤트 급증 여부 확인
  - `http.unhandled_error`
  - `payment.toss_confirm_failed`
  - `transform.failed`
  - `analyze.restore_failed_manual_action`
